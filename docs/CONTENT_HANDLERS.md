# 跨应用内容打开

文件管理器根据已安装应用的 `app.json` 发现文件处理者。点击普通文件时，一个处理者会直接打开文件；多个处理者会显示可翻页的应用选择列表；没有处理者时继续显示文件名和大小。

## 声明支持的文件

应用源码的 manifest 可以增加 `file_extensions`：

```json
{
  "abi": 1,
  "id": "books",
  "version": 10,
  "data_version": 1,
  "name": "书架",
  "background": true,
  "file_extensions": ["txt", "md", "markdown", "epub", "mobi"]
}
```

扩展名使用不带点的小写 ASCII 字母或数字。数组中的元素必须是非空字符串，不能重复。字段可以省略，也可以是空数组。资源包不能声明非空处理者列表。扩展名数量和字符串长度不设额外固定上限，仍受实际 manifest 读取和内存分配结果约束。

`tools/package_app.py` 校验并将字段复制到安装包；设备端包校验和元数据读取执行相同的格式检查。平台匹配最后一个路径分量的最后一个扩展名，忽略扩展名的 ASCII 大小写。只含扩展名的隐藏文件（例如 `.txt`）不匹配。

当前 books 声明 TXT、Markdown、EPUB、MOBI；图库声明 PNG、JPG、JPEG。处理者声明表示应用接受该格式的打开请求，具体文件是否能够解码由应用判断。

## 平台接口

公开声明位于 `src/ui/platform/app_content.h`，通过应用 SDK 公共头提供。接口在 UI 线程使用。

| 接口 | 行为 |
| --- | --- |
| `app_content_query(path, first, items, capacity, count)` | 检查文件并分页复制处理者 ID 和名称；`count` 返回全部匹配数量。 |
| `app_content_open(id, path)` | 重新检查安装位置、处理者声明、文件和恢复模式，随后将 intent 交给 `app_fwk`。 |
| `app_content_receive(intent, path, size)` | 将传入路径完整复制到应用提供的缓冲区，并验证文件和 TF 卡会话；普通启动返回 `-ENOENT`。 |
| `app_content_error(error)` | 返回可供界面显示的错误文字。 |

处理者发现只读取 catalog 和安装 manifest，不加载应用 ELF。选择列表持有字符串副本，catalog 刷新不会使界面保存的对象失效。实际打开时会再次确认处理者可用性。`app_content_open()` 返回 `RT_EOK` 表示消息已入队；模块加载和应用入口在框架后续调度时执行。

## Intent 和路径容量

平台仅将应用 ID 传给 `intent_init()`，完整文件路径由 `intent_set_string(intent, "path", path)` 写入。路径中的 UTF-8 中文、空格和等号会原样传递。平台不会将路径拼接为命令行，也不会截断后继续打开。

本地 SDK 的 `intent_int.h` 定义 `INTENT_MAX_LEN = 128`。`intent.c` 的追加规则要求累计使用字节数严格小于 128。总用量包括应用 ID 及其结束符、`path=` 和完整路径及结束符、请求序号 `r=`，以及 TF 路径的卡会话 `s=`。中文按 UTF-8 字节计数，序号和会话按实际十六进制字符串计数，因此不能用单一字符数表示所有路径的可用长度。

平台检查每次 `intent_set_string()` 的实际返回值。容量不足返回 `-ENAMETOOLONG`，分配失败返回 `-RT_ENOMEM`，均不会发送不完整请求。接收缓冲区不足同样拒绝复制。应用不得保存 `intent_get_string()` 返回的借用指针；`app_content_receive()` 返回的路径已经位于应用自有缓冲区。

## 已运行应用与页面生命周期

本地 SDK 的 `app_schedule.c` 在 RUN_APP 分支比较同一应用的新旧 intent 完整内容。相同内容只恢复应用；不同内容先将旧应用标记退出并重新入队。调度器随后让旧页面完成 ONPAUSE、ONSTOP、屏幕删除和页面节点释放；`schedule_apps()` 只有在页面列表为空时才将旧应用移入挂起列表。再次处理请求时，SDK 仍会查找并销毁挂起列表中的同 ID 实例，只有两个列表均不存在该 ID 才调用 `app_launch_new()`，随后由 `app_do(APP_EXEC_START)` 调用新入口。不能将“启动另一个应用时，新入口可能先于旧应用页面暂停”套用到同 ID 的 intent 替换流程。

每次内容打开都附带变化的请求序号，因此同一文件的重复打开也能够重新进入应用，已有 root／reader 页面按框架生命周期关闭。所有应用与页面切换均由 `app_fwk` 执行。

books 在 `app_main()` 中只复制请求并更新入口代次。在后台服务的 UI 处理阶段，只有当前页面是此次入口对应的前台书架页、应用仅剩该页面且显示空闲时，才关闭旧阅读会话、准备指定文件并创建阅读页面。旧 reader 存活或旧代次书架仍在前台时均不会替换阅读数据；即使入口提前调用，也会等待旧 UI 退出。`ui_bookshelf_include_path()` 为根目录书架之外的文件提供独立的活动条目，沿用现有阅读、缓存和历史保存接口；根目录列表已满也不妨碍打开子目录中的文件。替换外部条目前会排空历史写入，读取中的标题和路径不会引用已被替换的条目。

图库在入口复制请求，待图库服务启动后通过框架创建图片页。图片页再次复制模块持有的路径，跨页面消息不携带浏览页或 intent 的借用指针。页面暂停时暂停轮询并取消请求；图片页停止时删除定时器、取消请求、等待绘制结束并释放图片；浏览页停止时停止图库服务。

## 存储和恢复模式

平台在存储锁内检查文件与安装位置。文件必须是 `/flash/` 或 `/sdcard/` 下的普通文件，路径不能包含空分量、`.` 或 `..`。TF 请求包含发起时的卡会话，接收时卡已移除或被替换会拒绝请求；应用在延后打开前也再次检查会话。图库在恢复和读取结果时检查存储会话，失效结果不会继续显示。

恢复模式下平台拒绝内容启动，catalog 的动态加载入口也在加载 ELF 前执行恢复策略。平台不会绕过该加载入口。

## Host 验证

在 MSVC 开发环境中执行：

```text
python tools/tests/run_app_content_tests.py --asan
python -m unittest tools.tests.test_content_manifest tools.tests.test_package_capacity
```

测试使用本地 SDK 的真实 intent 序列化与入队复制代码，验证中文空格路径、扩展名匹配、处理者副本、重复请求、容量边界、分配失败、队列失败、TF 卡会话和恢复策略。books 生命周期测试执行 SDK 的实际 RUN_APP 分支和应用页面回调，覆盖已有 root／reader、后台页面、重复文件、显示等待以及旧页面释放；另行故意在旧 reader 的暂停和停止回调前调用新入口，验证旧 reader 和旧代次书架均不能提前消费请求。图库测试执行实际入口及浏览页、图片页回调，验证入口不释放旧图片、路径独立复制、后台暂停、停止清理顺序和 TF 会话失效。书架数据测试执行实际数据层代码，覆盖根目录列表已满、子目录中文路径、历史保存恢复、文件身份变化和关闭清理。

宿主替身模拟 RTOS 调度、存储与界面服务；RUN_APP 分支测试并非完整 SDK 调度器测试。上述真实调度全序依据 `app_schedule.c` 的列表查找、状态机和调度循环核对，不能由宿主同步退出替身单独证明。硬件显示、实际模块装卸和两种板型的集成验证仍需设备测试覆盖。
