# 书架应用解析与显示性能优化方案

本方案覆盖 TXT、Markdown、EPUB、分卷 EPUB 和 MOBI 的打开、分页、翻页与字号重排。目标是减少重复计算、文件访问和显示前等待，保持现有排版结果、阅读位置、应用生命周期及墨水屏刷新策略。

O1～O7 的确定性改造已落实到项目代码，下面保留改造依据、实现约定和验收方法。主机回归与板级编译结果见文末；实际设备上的耗时占比和加速比例仍需分段测量。MOBI 解压中间文件仍是有条件的后续选项，没有加入默认执行路径。

## 优化项目与收益范围

| 项目 | 解决的问题 | 主要受益场景 | 不解决的部分 |
| --- | --- | --- | --- |
| O1 转换缓存和分页索引持久化 | 非 TXT 关闭后删除转换结果、重新打开从头转换与分页 | 重复打开、恢复靠后的阅读位置 | 第一次转换和字体变化后的新排版 |
| O2 当前页优先与显示让行 | 后台计算高频唤醒 UI、抢占屏幕驱动，当前页完成后继续预备 | 连续翻页、重排、前台响应 | 解码和绘制本身的计算量 |
| O3 分块排版与结果复用 | 逐字符调度、重复状态读取、索引页与显示页重复排版 | 首次分页、字号变化、缓存未命中的翻页 | 面板波形发送 |
| O4 正文控件复用和插图预备 | 每页新建控件，有图页面在 UI 中读文件并生成位图 | 连续翻页、含图书页、往返翻页 | 原始插图首次解码 |
| O5 文档缓存读写合并 | 小块读写、重复定位、同步和重新打开文件 | 非 TXT 转换与分页，尤其 TF 卡应用 | 存储介质自身带宽和错误 |
| O6 MOBI 预扫描与目标索引优化 | 两遍处理及有序链表插入造成额外成本 | 首次打开 MOBI，链接密集的书籍 | 通用排版与控件构建 |
| O7 TXT 读取和字符预备协同 | 多个游标交替使用同一原文预读缓存，整书字符扫描重复解码 | TXT 首次分页、后台字符准备 | 已命中邻页缓存后的面板刷新 |

实现按模块并行，集成按依赖收口：O4 复用 O5 的独立读取游标，O7 复用 O2/O3 的任务优先级和分块边界。以下“改造前依据”描述优化前的代码，不代表现有实现仍在重复这些工作。

## 目标职责划分

| 执行位置 | 拥有的对象和工作 |
| --- | --- |
| 现有文档工作线程 | 原格式转换、转换缓存写入和提交、持久化文件工作、插图显示像素预备；不操作控件或 LVGL 字体 |
| 现有 UI 分步服务 | 阅读目标、字体度量、分页、相邻页布局和字形预备；独占这些状态 |
| UI 显示提交 | 更新控件、绑定已准备的图片、更新正文版本和实际显示的阅读位置 |
| 既有显示栈 | 字形绘制、缓冲区提交、面板刷新及完成通知；不改变波形、扫描和供电 |

复用 `document_t`、已有文档序号、`layout`、存储卡会话和应用服务生命周期。不新增独立导航栈、常驻分页线程或按页面创建线程。

处理链为：原格式 → 与字号无关的文档记录 → 当前排版参数下的页起点与页面布局 → 正文控件及图片 → 显示提交。布局缓存保留当前页和相邻页，不为全书保存所有控件或页面像素。

## O1 转换缓存和分页索引持久化

### 改造前依据

`document.c:cache_open()` 使用会话临时名称，`document_service_process()` 在会话结束后删除缓存。`document_view_open()` 从零建立页起点，恢复位置前须排到目标记录。TXT 的 `ui_reader.c:index_load()` 已有持久化索引，不替换其实现。

### 实现方案

1. 在 `STORAGE_APP_CACHE` 下建立非 TXT 文档缓存，继续由 `storage_app_path()` 决定卷。书架装在 TF 卡上时，缓存随卡保存。
2. 每本书保存三类文件：原样的文档记录 `.bin`、转换完成与来源元数据 `.meta`、最近使用的排版索引 `.idx`。文件名复用书架的卷类别和相对路径标识，元数据保留完整相对路径以校验名称碰撞。
3. **不在原文档记录前插入文件头，不合并或重新切分记录。** 现有 `document_cursor_t.record/byte` 继续指向相同字节。元数据的版本与 `DOCUMENT_CONVERSION_VERSION` 分开，单纯增加缓存不升级内容转换版本。
4. `.meta` 保存格式、来源身份、外部资源依赖、转换版本、图片转换参数、实际记录长度、标题和完成状态。页索引保存内容身份、排版身份、页数、页起点和目录位置，不保存指针或字体实例地址。
5. 先验证缓存，再按需打开 MOBI 私有库。转换缓存命中时不加载 `bk_mobi.so`，也不调用原格式转换器。分页索引命中后直接定位目标页，只准备目标页和邻页内容。
6. 转换完成但页索引尚未完成时，仅复用转换结果，继续分页；字体或排版参数变化时只重建 `.idx`，保留 `.bin`。

### 来源身份与失效

- 主文件沿用书架当前的大小和修改标识：TF 卡使用文件修改时间，内部 LittleFS 使用当前内容签名。复用扫描结果，不在打开路径重复计算整本书签名。
- 分卷 EPUB 校验相关章节包和基础包的清单。Markdown 另外记录实际使用的本地插图依赖，包括此前缺失的资源；依赖新增、删除或修改均使转换缓存失效。
- 绝对挂载路径和本次开机的卡会话号不写入可携带的永久身份。会话号只用于运行期间拦截失效访问。
- 转换器输出语义或图片转换参数变化使 `.bin/.idx` 失效；字号、字体内容签名、字重、行距、边距、实际正文尺寸和排版算法版本变化只使 `.idx` 失效。
- FAT 修改时间和现有非密码学签名不是内容完全相等的证明。保留这个现有身份边界，不为快速打开增加每次全书扫描。对保留时间戳的文件替换，可删除对应可重建缓存强制重建。

### 提交与资源释放

- 转换期间写临时文件，仍以已同步的完整记录边界供当前会话阅读。
- 工作线程完成写入和同步后，在 `storage_lock()` 内关闭本会话所有读句柄，并通过 `storage_file_commit()` 提交正文，最后提交 `.meta` 完成标记。所有游标读取及游标增删都使用同一存储锁，因此不需要额外的 UI/工作线程确认状态。读端保留逻辑游标，下一次读取重新打开已提交文件，期间继续显示已有页面。
- 新正文替换旧正文前，先通过现有元数据保存机制提交“未完成”状态，成功后才替换正文，避免 FAT 恢复旧备份时复活错误的完成标记。不覆盖仍被另一个会话使用的缓存。中途失败最多损失可重建缓存，不允许旧 `.meta` 为新正文提供错误身份。采用现有 FAT 备份恢复流程，不另建文件事务系统。
- 完成的缓存不因正常退出删除；未完成的临时缓存可以删除。打开时校验元数据、文件长度及索引边界，读取时保留记录长度和偏移检查；发现损坏则废弃该缓存并重建。
- 页索引由 UI 生成，冻结一个只读快照交给工作线程保存。快照持有期间不能被重排或退出释放；若保存快照所需内存实际申请失败，则跳过本次索引持久化，现有阅读和内存索引继续工作。总页数照常只触发一次底栏更新，不等待索引写盘。
- 存储实际空间不足时，只回收不在使用中的书籍缓存，按缓存中记录的最近使用时间选择最旧的一组，不删除原书、进度或应用文件。回收后至多重试当前失败的写入一次，不重启转换、不向已发布的正文重复追加；仍失败则沿用存储错误提示。缓存不设置单本文档固定容量门槛。

### 兼容和验收

保留原有阅读历史结构及双槽保存。缓存升级不清空进度；同一源文件和转换版本下，旧记录位置必须恢复到相同正文。旧 `doc-*.bin` 仍作为临时残留清理，不误认作完整缓存。

验收要求：再次打开时原格式转换调用次数为零；同排版参数时全书分页次数为零；修改字号只重排；更新源书或资源后不读旧缓存；转换或提交阶段退出、拔卡、写入失败都不能留下可被误用的完成标记。

## O2 计算与显示提交分离

### 改造前依据

`pages.c:books_process()` 把主要分页处理放在 `lv_refreshing_done()` 条件内。相邻页预备可与面板发送重叠，但依赖已产生的页索引。`main.c` 在处理一轮 UI 后按 LVGL 返回值休眠，最长 20 ms。

### 实现方案

1. 将一次阅读 UI 步骤拆为“推进计算”和“尝试提交”。阅读 UI 服务只在 `lv_refreshing_done()` 为真时执行这两个步骤。当前 UI 主线程优先级为 10，默认 `lcd_task` 为 12；高优先级阅读计算会挤占驱动的灰度转换、旋转和数据准备时间。因此，刷新忙期间暂停 UI 侧分页和字形预备，保留待翻页目标，显示空闲后再处理。现有文档工作线程不受此门控影响。
2. 计算与字形预备仍在 UI 线程。访问字体缓存遵守现有互斥；涉及生成或淘汰像素时，保留 `lv_draw_wait_for_finish()`，它等待绘图而非完整面板波形。不得以解除面板等待为由取消 EPIC 资源保护。
3. 任务优先级固定为：取消和介质变化 → 当前目标页/恢复位置 → 翻页方向的邻页 → 反向邻页 → 后续全书分页 → 远处字符预备。下一页尚无索引时，先推进到下一页边界，不能让低优先级扫描抢先占用预算。
4. 分页与字形预备共用每轮 8 ms 的现有软预算，避免各自执行 8 ms 后叠加阻塞。请求页已经准备好时立即进入提交，不消耗剩余预算做相邻页或全书计算。截止点设在字符块、完整行或完整记录；一次存储访问或单字栅格化仍可能超过软预算。
5. 阅读步骤返回空闲/等待、后台预备、当前目标三类工作状态。只有当前页所必需、且可立即推进的计算请求 1 ms 后继续；相邻页、全书分页及远处字形预备用原有 LVGL/最长 20 ms 的普通 UI 节奏。等待文档数据、图片工作线程或显示空闲时，不请求快速循环。复用项目侧“下轮 UI 工作期限”接口，不改变 `epd_background_t` 回调职责。
6. 每次服务调用前消费上一次期限，停止服务时清除期限，防止已经退出的应用留下高速空转。工作线程仍通过状态快照发布结果，UI 最晚在原有轮询期限内发现新数据；不为这一项增加新的跨线程事件框架。

导航和输入顺序维持当前实现；此项不提前提交尚未完成的页面，也不把预备目标当作实际阅读位置。加入项目导出接口后，固件与动态应用需按既有配置标识重新配套构建。

### 验收

在模拟面板忙、绘图空闲时，阅读 UI 步骤调用次数、分页游标、字形预备进度和控件均不变，也不申报快速唤醒。忙状态解除后处理保留的最终目标；当前页完成后，不再因后台工作请求快速循环。分别覆盖 TXT 和结构化文档的当前页计算、缓存命中、等待输入、等待图片、菜单重排及取消，验证总页数仍只更新一次底栏。板上使用相同书籍连续翻页，比较驱动数据准备段和 `Take` 总耗时。

## O3 分块排版与结果复用

### 改造前依据

`document_view.c:page_step()` 每次处理一个字符或结构事件，并读取包含标题和错误文字的文档状态；英文单词前瞻与逐字放置会重复查询字宽。索引阶段构造页面内容，完成后主要保留页起点，显示阶段再构造页面布局。TXT 也会在索引、显示及邻页准备中重复度量部分行。

### 实现方案

1. 非 TXT 将逐字符外层调度改为文本块推进。每个短步骤取得一次精简快照，只包含已发布边界、完成和错误状态；标题等低频数据由外层 UI 服务更新。
2. 快照代表本轮可读取的上限。新发布的数据留给下一轮；每个块边界检查取消，实际 I/O 前后仍检查介质，不能把取消和拔卡检查全部移出读取路径。
3. 同一文本块先解码出字符及宽度，英文前瞻与实际放置复用这些结果。沿用现有字体描述缓存，不再增加一张全书字宽表。保持制表符、换行、英文整词换行、混合样式、链接和图片的现有规则。
4. 让索引、目标页和邻页共用一个分页核心：统一消费文字并计算边界，通过可选输出收集器决定是否生成文字与布局块。远处页只计算边界；当前目标及邻页同时产出可直接使用的布局。
5. 当前索引刚好计算到目标页或邻页时，通过转移或交换已有页缓冲保存结果，不再从同一页起点重新计算。TXT 同样在索引经过所需页面时收集已换行文本，交给现有三页缓存。
6. 分页索引键增加独立的排版算法版本。若实现保持页边界逐项一致，不改变文档记录版本；若修正排版规则，则只使排版索引失效，阅读位置仍按正文位置恢复。

### 验收

用固定字体度量输入对比优化前后的全部页起点、文字序列、布局块坐标、目录和链接位置。覆盖 UTF-8/GBK TXT、跨记录英文单词、中文、空段落、粗斜体和图片边界。记录每千字符的状态快照次数、字宽查询次数、同一页重复排版次数。未缓存和实际分配失败时仍能按需排版。

## O4 正文控件复用和插图预备

### 改造前依据

`document_view_bind()` 每次建立新正文根对象及子控件，再删除旧根对象。图片在绑定过程中通过 `document_image_load()` 同步读取、展开、缩放为 RGB565。相邻页目前只预备布局和源字形。斜体包装器每次绘制还会申请并生成倾斜位图。

### 正文控件

- 阅读页创建一次正文根对象，保留一个按需增长的文字/图片控件集合。提交时复用同类控件，更新文字、样式、坐标和链接；多出的控件隐藏，类型变化时更换必要对象，不重建整页容器。
- 同一控件只注册一次事件回调，链接目标使用当前绑定数据；不能重复累积回调或保留上一页链接。
- 页面布局和必须的图片资源准备完整后才提交，保留上一页直到提交开始。释放旧图片、替换仍被绘图引用的资源前，等待已有绘图结束；一轮 UI 提交之后再进入 LVGL 绘制。
- TXT 已使用固定正文标签，继续复用，不改成逐字或逐行控件。

### 图片预备

- 以现有文档会话、排版身份、图片记录偏移和目标尺寸作为缓存键。当前页图片不可淘汰，优先准备翻页方向邻页，反向邻页其次。
- 复用文档工作线程准备原始 RGB565 像素，不在工作线程创建控件或调用字体接口。UI 收取像素后建立显示描述、执行必要缓存写回，再绑定图片。
- 工作线程目前在 `convert()` 中同步运行整本转换。为避免图片请求一直排到转换结束，在已完成记录的发布边界增加协作检查点：先释放存储锁，再处理已经发布且可读取的目标页/邻页图片，随后继续转换。目标图片尚未发布时继续转换，不能等待自己尚未生成的数据。
- 像素任务使用独立读取游标，不借用 UI 读取句柄。会话取消时清除未执行请求；在途任务退出后才能回收文档。`stopped` 表示转换和图片等文档任务均已停止，不能只表示转换函数已经返回。
- 字号、边距或目标页变化后，UI 只接收当前会话和排版身份匹配的结果，其余像素释放。复用已有文档序号和存储卡会话，不另建任务世代表。

### 内存与冷页退化

RGB565 位图成本为 `对齐后的行字节数 × 高度`；620×1040 图片约为 1.23 MiB，不能承诺前后两页大图始终驻留。预备按实际分配结果执行，先释放非当前页的可再生图片。可选预备失败只跳过预备，不中止阅读；真正切到冷图片页时提交优先任务，完成前保留旧画面。当前目标页在回收可选缓存后仍分配失败或读取失败时，发布明确失败结果并沿用现有错误提示，不无限重试、不一直显示准备中，也不提前保存该页为阅读位置。

斜体最终位图纳入现有阅读字形缓存的可选扩展入口，键包含字体实例、字符和样式，不建立第二套无上限缓存。基础字形引用在派生期间保持有效，派生位图使用同一预算和实际分配规则；无法缓存时保留当前即时生成路径。该扩展主要改善斜体较多的文档，不作为普通中文书提速的前提。

### 验收

相似文本页连续翻页时不再每页创建/删除正文根对象，控件数量达到高水位后应稳定。图片缓存命中时，显示绑定路径的文件读取和像素转换次数为零。切换链接页、字号、退出及拔卡后不得出现旧回调、过期图片或绘图释放竞争；压力测试记录实际 PSRAM 峰值。

## O5 文档缓存读写合并

### 改造前依据

`record_write()` 分别写记录头和正文。`cache_publish()` 首批以 2 KiB、后续以 8 KiB 或经过 50 ms 为条件执行同步，再发布可读边界。`document_read()` 每次定位文件，发现新发布版本时重新打开，以满足 LittleFS 文件可见性。

### 实现方案

1. 写端增加可选聚合缓冲，优先采用与现有后续发布批次相同的 8 KiB 大小。合并系统调用，不合并文档记录；大图片连续数据可直接分块写入。缓冲分配失败时回到当前直接写入路径。
2. 明确区分逻辑生成末尾、实际写入末尾和同步后已发布末尾。正文位置采用逻辑偏移；只有完整记录已经写出且同步成功，才允许推进读端边界。
3. 首批、EOF、目标页等待数据和正常关闭时及时发布；后台连续转换继续按批次发布。保留现有 50 ms/8 KiB 作为初始策略，不先靠任意增加等待时间减少同步次数。
4. 读端设置独立的顺序游标与可选预读窗口，索引、显示/邻页和工作线程图片读取不能互相修改游标。记录头和同一窗口中的正文一次读取获得；连续读取不重复 `lseek()`。
5. 已发布区域只追加不修改。旧句柄可继续读它原来可见的区域，只有请求越过其可见末尾时才按最新发布边界重新打开。完成后切换文件名时必须重新绑定。这样减少重新打开次数，同时保留 LittleFS 的同步语义。
6. TXT 的 `index_save()` 仍在 UI 线程同步写入，改为在索引完成后将不可变快照交给既有文档工作线程保存，与 O1 使用同一个索引保存机制。阅读进度继续使用现有后台双槽保存，不重复建设。

### 验收

对相同输入比较生成记录的完整字节流，必须一致。统计 `read/write/lseek/open/fsync` 次数和耗时、缓存命中量及存储锁等待时间。覆盖短写、短读、同步失败、部分记录及新发布数据；读端不得访问未同步区域。TXT 总页数完成时不再由 UI 执行索引 `fsync`。

## O6 MOBI 预扫描与目标索引优化

### 改造前依据

`mobi_converter.c` 第一遍扫描跳转目标并判断封面是否已出现在正文，第二遍输出插入锚点后的正文。`scan_links()` 已采用连续块搜索，文件读取已有 16 KiB 预读，HUFF/CDIC 字典也已复用，不能把这些现成功能再次列为新增优化。

`add_target()` 每次从有序链表头部查找插入点；大量目标时会出现多次遍历。`part_at()` 也按序号反复从链表头查找章节。正文输出依赖完整目标集合，直接省略第一遍会改变链接和封面行为。

### 实现方案

- 保留两遍语义及现有 `mobi:<part>:<offset>` 身份。O1 命中时整段跳过，两遍成本只发生在真正需要转换时。
- 用按需增长的目标数组收集位置，扫描结束后按 `part/offset` 排序去重，第二遍顺序读取；目录标题冲突保留现有“第一个非空标题”的规则，以原收集次序作为稳定次序。采用有确定复杂度的归并或堆排序，不依赖未经核查的库排序最坏性能。
- 将按序号反复查找章节改为顺序迭代；需要随机章节访问的路径建立小型指针索引，并检查实际分配结果。
- 单独测量第一遍和第二遍的解压次数、解压耗时与存储读取耗时。重复解压占比确实显著时，将第一次遍历的解压连续块顺序暂存为可选工作文件，让第二遍读取；先在实际卡和内置存储上证明“写后再读”比重复解压快，再启用该路径。空间不足或暂存失败时关闭并删除暂存，回到当前重解压路径，不影响正式转换缓存。第二遍若读取暂存失败，按原章节和解压偏移恢复原始输入，不能从头重复向已经发布的正文追加记录。
- 不以加载整本 RAWML 或全书 PSRAM 常驻作为提速前提，不把完整扫描延期后留下未解析的链接。

### 验收

比较 MOBI/KF7/KF8、PalmDOC/HUFF、跨章节/反向链接、重复链接、目录以及正文重复封面样本的记录字节、链接和图片顺序。必须保持 `DOCUMENT_CONVERSION_VERSION` 对应的输出不变和旧阅读位置可用。暂存解压结果为证据驱动优化；若基准无收益，保留数组索引优化，不引入该 I/O 路径。

## O7 TXT 读取和字符预备协同

### 改造前依据

`reader.c:raw_read()` 为同一本书维护一个 8 KiB 原文缓存，分页、显示、邻页和整书字符扫描从不同位置调用读取，可能相互挤掉窗口。`ui_reader_prepare_process()` 又从书首扫描字符；首次分页已经读取并解码过同一批文字。

### 实现方案

- 把原文预读状态从全局唯一窗口拆为会话内的独立读取游标，优先保证全书顺序索引和当前/邻页读取不互相覆盖。沿用当前 8 KiB 窗口大小，按需申请；可选游标窗口申请失败时使用原有共享读取退化路径。
- 首次分页从已解码的字符块中顺带收集唯一字符，加入待预备集合，不在度量回调中生成字形。实际栅格化继续由低优先级 UI 预备步骤完成，邻页字符始终优先。
- 区分“已发现字符”和“已经处理过预备机会”，不能把尚未预备的字符直接标为完成。位集合容量根据 Unicode 表示范围计算；新增集合也按需申请，失败后继续现有单游标扫描，不影响正文。
- 持久化分页索引命中时没有全书分页过程，保留原有分步字符扫描作为空闲工作；首次分页已经覆盖的区域不再重复扫描。
- 共享字形缓存预算和 Tiny TTF 回调不在本项中扩大，不以“整个 TTF 已在 PSRAM”推断全部字形像素也已缓存。

### 验收

TXT 原文字节映射、CRLF、UTF-8 跨块、GBK 转码和页起点保持一致。比较实际原文读取字节数、定位次数和重复解码量；在分页和字符预备并行推进时，顺序索引游标不得因邻页访问反复回读。旧索引命中和可选缓存分配失败时仍可正常翻页。

## 计时与验收方法

### 统一指标

计时沿用 RT-Thread 单调 tick，并以 `RT_TICK_PER_SECOND` 换算毫秒。短步骤累计时间同时记录调用次数；如果 tick 分辨率不足再复用板级高精度计时接口。各阶段可重叠，不能把并行阶段墙钟时间直接相加当作总时间。

| 指标 | 起点与终点 |
| --- | --- |
| 请求至页面可提交 | 接受打开/翻页目标 → 目标布局、控件所需数据和图片均准备完成 |
| 请求至显示完成 | 接受同一目标 → 对应屏幕刷新完成；须关联实际提交目标，不能用任意一次 busy 变空闲替代 |
| 全书转换时间 | 转换任务开始 → 完成的记录同步并发布 |
| 全书分页时间 | 当前排版开始 → 最后一个页起点确定 |
| 恢复时间 | 接受打开/重排 → 原正文位置所在页可提交 |
| 计算与等待 | 度量/解压/位图处理累计时间；存储及锁等待；等待更多记录；等待显示提交；主动让出时间分别统计 |

现有实现关闭文档时输出 `[document] io`，分别记录 read/write 次数与字节数、seek/open/sync 次数；命中转换缓存时输出 `cache-hit`。目标页准备完成时输出 `target-prepared`，包含本次目标耗时和累计的块数、字符数、字宽查询数、布局数、复用数及索引命中数。沿用现有 `[mobi]` 阶段日志和字体 hit/miss；`first-page-ready` 只表示控件准备完成，不能代表墨水屏已经完成刷新。完整的请求至面板完成关联、锁等待分布和板上 P95 仍按上表测量，不能从这些汇总计数直接得出。

MOBI 的逐阶段解压、读取和锁等待汇总默认关闭。诊断构建前在 PowerShell 设置 `$env:BOOK_MOBI_MEASURE = '1'`，正常执行应用构建；构建后执行 `Remove-Item Env:BOOK_MOBI_MEASURE`。phase 0 为头部/资源准备，phase 1 为链接预扫描，phase 2 为正文输出。设置只影响项目侧 MOBI 适配层，不修改第三方解码器。比较主机回归时可以分别运行 `run_o6.py --measure 0` 和 `--measure 1`。

### 对照场景

1. 分别测试 TXT、MD、EPUB、分卷 EPUB、KF7 和 KF8；覆盖纯文字、英文、中文、粗斜体和插图。
2. 分开记录无文档缓存、转换缓存命中、分页索引命中、相邻页命中及冷页五种状态，不用同一个“打开耗时”混合统计。
3. 使用相同书籍、字体、字号、安装卷、CPU 配置和全刷周期，分别测试开头、中间、靠后位置及字号重排。书籍校验值仅用于固定测试输入，不加入每次打开路径。
4. 连续向前、向后和快速合并翻页，记录目标数量、实际提交页和缓存命中率；全刷与局刷样本分别比较。
5. 同一条件重复测量，保留样本数量并报告中位数、P95 和最大值；P95 样本不足时不把单次耗时作为稳定结论。未建立板上基线前不承诺固定毫秒数或倍数。
6. 每项先满足前文的结构性验收，再确认目标场景提速且没有在正文正确性、取消响应和内存峰值上出现不可接受的退化。使用主机耗时只能证明主机结果，不能替代板上存储和显示测量。
