## 实现约束

应用的可执行文件与数据分目录保存，更新及卸载代码不删除用户数据。TF 卡每次挂载均建立新的会话；确认只对当前会话有效。加载应用意味着启用入口及声明的后台服务，不自动打开所有应用页面。

动态模块共享系统地址空间。退出依靠取消与有序清理；超时不得释放仍在执行的代码。突然拔卡可能丢失未写入数据，也可能导致 FAT 损坏；软件必须让失败返回并拒绝旧请求，而不是等待保存成功后才能退出。

拔卡后统一停止动态应用，包括可能读取 TF 文件的内部应用；完成释放后内部应用可以重新运行。退出等待超过 35 秒时保持 TF 隔离并继续等待清理，不强杀线程；内置 UI 能否继续响应以其回调能够返回为前提。SD 组件采用 Solution 的探卡 `1000 × 30 ms`、移除 `100 × 30 ms` 等待预算；SDK 请求超时后保持隔离，不重复提交或假定原请求已取消，需要重启恢复。

本地 SDK 的 `dfs_elm_close()` 仅在 `f_close()` 成功后释放文件对象；`f_close()` 的写盘同步失败会提前返回，DFS 也不会完成对应句柄回收。因此，拔卡引起关闭失败时，平台可能检测到遗留句柄并拒绝卸载及挂载替换卡。原调用者无法释放时需要重启，不能通过强制释放仍可能被引用的对象绕过。此项保留 SDK 实现，不新增 SDK 改动。

同一 ID 的重复安装仍优先使用内部版本；迁移不合并两个独立安装的数据。目标已有数据时保留目标与源，目标为空才复制、核对、发布后清理源。空间不足、复制失败或校验失败时不启动待迁移卷上的应用，不删除唯一数据副本。可重建缓存不迁移。
