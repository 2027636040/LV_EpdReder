# 开发意图与设计决策

## 1. 平台定位

本平台面向墨水屏设备，以满足不同使用者的需求为出发点，主要服务三类使用者：

- 普通使用者：使用、安装应用，通过界面调整已有功能。
- 应用开发者：使用平台公开接口开发动态应用，编写应用界面和业务逻辑。
- 平台与底层开发者：开发和集成公共组件，完善平台接口，开展 SDK、驱动和板级开发。

应用开发者是本平台的主要服务对象。平台通过可复用的组件、统一的接口和完整的开发资料，降低应用开发的学习成本，让开发者能够把精力放在应用功能和使用体验上。平台的稳定性和可扩展性围绕这一目标持续完善。

平台同时提供一套墨水屏设备参考设计，把公共能力组合成可编译、可烧录、可使用的整机软件方案。

平台提供统一的内置系统界面，以 Launcher 作为桌面和应用启动入口，并提供文件管理、设置等系统操作。用户点击应用图标后，Launcher 发起打开请求，由模块加载器加载对应应用。

## 2. 应用开发与运行

应用以动态模块形式交付，将程序、资源、入口图标和应用信息组成完整安装包。用户通过安装、更新和卸载应用扩展设备功能，开发者可以独立构建、测试和发布自己的应用。桌面直接读取应用名称和独立图标来组织入口。

平台向应用提供存储、网络、时间、字体、输入、后台任务和公共界面接口。应用通过这些接口完成业务，把可复用的能力继续沉淀为公共组件。组件和接口的设计优先参考 SDK 与 solution 中适合本项目的做法。

应用和页面使用 SDK app_fwk 管理导航与生命周期。页面进入前台时读取最新数据，恢复选择、滚动位置和输入内容；页面离开前台时暂停界面专属工作，销毁时释放自有资源。书架、阅读、阅读菜单和设置之间保持自然、连续的返回关系。

平台通过受管服务组织天气同步、书籍扫描、分页、缓存准备和数据保存。后台任务与界面通过数据快照交接，由 UI 线程完成控件更新和依赖 LVGL 的处理。应用退出、更新或介质移除时，由平台协调任务停止和资源释放，保持页面、业务与模块生命周期的一致性。

## 3. 交互与墨水屏显示

界面保持简洁，突出内容和主要操作。桌面展示应用入口，底部提供快捷信息；应用较多时通过左右滑动切换桌面，并显示页码指示点。

普通使用者通过界面调整已有功能。系统设置按照显示、无线和网络、存储、应用管理及关于设备组织，设置修改即时生效。文件管理提供内部存储和 TF 卡入口，并能把选中的文件交给相应应用打开。

平台统一处理触摸和按键输入。专用设备采用触摸与电源键，通用开发板通过输入适配使用方向键。刷新期间继续接收操作，连续方向操作可以合并，确认和返回保持操作顺序，阅读页保留待翻页请求。

刷新策略兼顾显示质量与交互连贯性：

- 进入应用、退出应用和切换页面时执行全刷，并重置全刷周期计数。
- 同一页面的内容更新沿用用户设置的全刷周期。
- 时间、电量和蓝牙标识等状态栏自动更新采用局刷，单独更新时保持周期计数不变。
- 界面根据业务数据变化更新内容，文字变化判断使用保存的原始文字。

显示驱动负责波形、面板扫描和电源控制。局刷保留灰度未变化的像素，刷新完成后关闭面板电源。应用通过统一界面接口获得这些显示行为。

## 4. 存储与数据管理

应用安装在哪里，应用的程序、资源、数据和缓存就保存在哪里，让 TF 卡能够携带应用及其使用记录。应用持久化数据统一使用文件系统中的应用目录。

内部 NOR 使用 LittleFS，TF 卡使用 FatFs，由平台提供统一路径和文件访问接口。应用可以读取内部存储和 TF 卡上的内容，业务记录按应用安装位置保存。例如，书架可以打开卡上的图书，阅读进度仍保存在书架所属的数据目录中。

系统设置和系统所用字体保存在内部存储。用户从 TF 卡选择字体时，先将字体导入内部存储，再应用到界面，保证拔卡后字体仍能继续使用。

应用更新保留业务数据，并按数据格式需要完成迁移。数据通过后台任务保存，在退出和关机等节点完成必要同步，使阅读位置、学习记录和应用配置能够连续使用。

TF 卡拔出时，平台协调动态应用停止工作并释放文件和页面资源。再次插卡后，先完成挂载，再提示用户是否加载卡内应用。每次加载使用新的存储会话，使后续文件访问对应本次插入的卡。

## 5. 联网与应用协作

平台向多个应用提供统一的网络状态和网络变化通知。PAN 与 Wi-Fi 接入相同的网络接口，应用按照网络是否可用发起请求，连接方式与连接路径由系统管理。

网络就绪后自动同步系统时间，使用阿里云 NTP。天气等应用按照各自的业务周期同步内容，并在网络恢复后继续处理请求。

网络访问复用公共 HTTP 客户端和 SDK 证书机制，保留 HTTPS 证书校验。请求结果提供清楚的失败阶段，方便定位连接、证书、响应读取或业务解析问题。

应用可以向平台发布简短摘要，供平台提供的信息看板（桌面、锁屏等）显示。平台保存摘要内容并记录变化，使多个界面能够使用同一份业务信息。

文件管理器根据应用声明的文件类型查找处理者，通过统一入口打开图书和图片。应用在接收文件后继续使用自己的页面、阅读位置和业务设置。

## 6. 平台自带应用

平台根据市场需求，提供完整应用、应用市场、多端互联（小程序、网页）以足够应对日常使用，也为应用开发者提供可阅读、可复用的开发实例。

应用说明、设计文档和示例代码共同帮助开发者理解平台接口，并把已有做法应用到新的业务中。

## 7. 电源管理与设备扩展

锁屏保留应用上下文，以快速恢复原页面和操作状态为目标。设备空闲时结合任务状态进入低功耗运行，屏幕在刷新完成后关闭供电。

关机保存必要的业务状态，关闭外设；再次开机时重新初始化系统并加载数据，恢复阅读位置和应用配置。充电状态下保持关机，由用户决定何时开机。

设备升级从内部文件系统或 TF 卡读取更新包，由独立升级程序完成主程序和资源的安装，并显示安装进度。

围绕同一套公共接口扩展 Wi-Fi 接入、语音输入和新的内容应用，让设备能力能够随着硬件和应用逐步增加。

## 8. 开发支持与交付

平台为应用开发者提供公开接口、开发示例、独立构建入口和配套开发包。开发者可以单独或批量编译应用，也可以选择出厂预装应用，由构建流程生成完整的固件、应用包和文件系统镜像。固件与应用按照兼容关系配套构建和分发。

构建依赖的字体、图标、预生成词库及其他资源纳入版本管理。正常构建直接使用准备好的资源，并随应用提供来源和授权说明，方便内部开发者与社区开发者复现工程。

动态应用故障使用 SDK 已有的现场保存、导出工具和模块运行对象定位。开发者保存每次发布的主固件、动态模块、配套符号、源码与配置，根据模块实际装载地址在 GDB 中加载符号。诊断资料使用标准工具可以读取的形式，便于开发者和 AI 分析。设备提供恢复入口，供用户处理影响正常启动的问题应用。

文档以仓库内的网页知识库组织，覆盖平台架构、应用开发、应用设计、构建部署、故障诊断和技术储备。文档与代码一起维护，让开发者能够理解设计意图、找到接口用法并完成实际开发。

通过完整应用、可复用接口和清楚的开发资料，支持社区开发者持续贡献应用和组件，使平台能够用于不同的墨水屏设备与使用场景。
