## 统一网络入口

`src/services/net/network.c` 维护当前可用路由快照，事件订阅节点按需申请、注销时释放，不设固定订阅数量上限。
天气、NTP 和动态应用只依赖 `network.h`，不再自行连接 PAN 或查找蓝牙网卡。

`ready` 表示所选网卡已启动、链路正常、具有 IPv4 地址和网关；PAN 还要求 Profile 已连接。
它不表示已经探测互联网，也不能保证指定服务器可达。DNS、TLS、HTTP 错误仍由请求处理。

设置 → 无线和网络 → 网络方式支持以下选择，并随现有系统设置持久化：

- 自动：WiFi 就绪时优先 WiFi，否则使用 PAN。
- PAN：只使用 PAN；不可用时报告离线，不暗中改用 WiFi。
- WiFi：只使用 WiFi；尚未接入 WiFi 驱动时报告离线。

适配层通过 `network_register_interface()` 登记 SDK 的双字符设备名。
当前 PAN 使用 `b0`；后续 WiFi 驱动应登记实际名称，而不是由应用猜测。
lwIP 状态变化回调只记录事件，网络线程随后在 `tcpip_thread` 中读取路由并设置默认网卡。
DOWN/REMOVE 回调可能早于状态真正改变，因此不在该回调中直接宣布网络就绪。

每个网络来源分别保存 DNS。当前 SDK 在 DHCP 发布地址前处理 DNS 选项，首次地址变化时保存对应 DNS；
静态配置、相同地址的 DHCP 续租及适配器迟注册时，应调用 `network_set_dns()` 提交该接口的 DNS。
切换默认网卡同时恢复所选接口的 DNS，驱动适配层不得另行长期占用默认路由。

有效路由、地址或链路代次变化时更新 `generation`，投递所有订阅者各自的事件位。
事件可合并，但代次变化仍使在途天气/NTP 请求失效。业务线程读取完整快照，不保存 `netif *`。
天气和 NTP 的套接字绑定当前本地地址，并在等待期间检查网络代次。

### 订阅规则

```c
struct rt_event event;
rt_event_init(&event, "consumer", RT_IPC_FLAG_FIFO);
uint32_t token = network_subscribe(&event, 1);
/* token == 0 表示注册失败；成功时立即收到一次初始状态通知。 */
/* 工作线程等待事件，醒来后调用 network_snapshot()。 */
network_unsubscribe(token);
rt_event_detach(&event);
```

通知与注销使用同一把互斥锁。注销返回后，不会再向该订阅投递事件，此时才允许销毁事件对象。
网络线程不保存或执行应用函数指针，慢速应用也不会阻塞其他订阅者执行回调。
订阅变化不会自动触发 LVGL 重绘。

## 受管后台线程

`src/services/app_service.c` 按需登记长期任务，包括安装后的天气模块任务，不设固定任务数量上限。
每个独立线程任务栈为 2～32 KiB，优先级为 20 到 `RT_THREAD_PRIORITY_MAX-1`。
任务记录、订阅、线程或模块引用申请失败时回收本次申请并报告启动失败。
线程栈和优先级范围不是应用全部堆内存的强制配额；当前 SDK 模块分配器与图像共享 PSRAM 池，且可能回退 SRAM。
装载前不按空闲内存阈值或“ELF 文件大小 + PT_LOAD 跨度”拒绝模块；该大小仅用于辅助库装载前的字形缓存回收，之后由分配器实际尝试申请。
SDK `dlelf.c` 的装载区、符号表和符号名分配失败均返回 `-RT_ENOMEM`，由 `dlmodule_load()` 释放临时文件镜像并销毁未完成的模块。符号数量仅计入已经完成的符号名，清理时不会访问尚未分配的名称。

动态应用清单声明 `background: true`，并导出：

```c
static void background_run(epd_service_t *service)
{
    while (!epd_service_cancelled(service))
    {
        uint32_t events = epd_service_wait(service, RT_WAITING_FOREVER);
        if (events & EPD_SERVICE_STOP) break;
        if (events & EPD_SERVICE_NETWORK)
        {
            network_snapshot_t snapshot;
            network_snapshot(&snapshot);
            /* 在本线程处理业务，向 UI 发布受锁保护的数据快照。 */
        }
    }
    /* 关闭本任务的请求、文件和自有资源，然后返回。 */
}
const epd_background_t epd_app_background = {background_run, 4096, 24, true, NULL};
```

内部后台应用在开机目录枚举、安装/更新完成后启动，不需要先打开页面。
TF 卡应用还必须通过本次插卡的用户确认及数据迁移；普通挂载不意味着允许执行模块。
显示入口图标本身仍不装载程序；声明常驻后台才会被服务管理器主动装载。
页面打开与后台各持有一个 SDK 模块引用。页面 ONSTOP 只释放页面引用，后台继续运行。

停止顺序：阻止新打开 → UI 线程退出该应用页面 → 置停止标志并唤醒任务 →
任务取消请求、关闭资源并返回 → 等待在途模块命令返回 → 注销网络订阅 → UI 线程释放后台引用。
包装线程在公布完成后不再访问模块代码或服务对象，因此可以在 UI 线程执行最后一次 `dlclose()`。
不以 `rt_thread_delete()` 强杀仍在运行的模块任务，也不允许应用另留无人管理的线程或外部回调。
页面专属定时器和对象仍需应用在对应生命周期中清理。

### UI 线程分步任务

需要使用 LVGL 字体度量的任务不能与 UI 并发操作字体缓存。此类应用在
`epd_app_background` 中仅设置 `ui_process`，不设置 `run`、网络订阅、线程栈或优先级：

```c
const epd_background_t epd_app_background = {
    .command = books_command,
    .ui_process = service_process
};
```

平台每轮 UI 处理调用一次步骤函数；应用必须将工作拆成有限步骤，不能在其中阻塞等待网络或事件。
`books.so` 按 UI 软时间预算推进索引，只在前台执行待翻页和控件更新，计算过程中不重绘。
总页数完成时仍只更新一次阅读底栏。离开页面后模块由服务引用保持，索引可以继续完成。

步骤函数签名为 `bool service_process(epd_service_t *service, bool stopping)`。
停止时平台先禁止新的命令调用，并等待文档工作线程和在途命令返回，然后才以 `stopping=true` 调用 UI 步骤函数。步骤函数等待页面全部销毁及显示空闲，
关闭文件并释放自有字体、分页/书库缓存和互斥锁，再返回 `true`；随后平台释放最后的服务模块引用。
普通运行期间返回 `false`。服务调度集中在 UI 主循环；存储释放阶段由释放流程推进同一调度器。

`run` 与 `ui_process` 至少指定一个，也可以同时存在，两部分共用一个服务槽和同一个模块引用。
书架的 `run` 串行解析文件和解码插图；`ui_process` 负责字体度量、分步分页和页面结果绑定。
两部分分别记录完成状态。工作回调尚未返回时，不调用停止清理用的 UI 步骤，也不卸载模块。
清单仍使用 `background: true`，因此安装后和开机时也会装载阅读服务，用于恢复最近阅读摘要。
只显示入口图标不要求装载模块。

`modules/hello` 保持原触摸示例页面，同时加入仅等待网络事件的后台任务。
返回主页后线程和模块引用保留；更新/卸载时任务退出。日志不触发屏幕刷新。

## 天气与校时

天气仍由一个 12 KiB 栈的线程串行处理同步、城市验证、配置导入和持久化。
页面关闭不会停止天气线程。空闲时按下一业务期限等待事件，不再每秒轮询 PAN。
首次联网、重连或切换网络后静默同步；保留固定 30 分钟周期和失败后至少 5 秒的受控重试。
普通唤醒不会缩短失败后的重试间隔。离线保留待同步标志；手动请求可以唤醒线程。
天气结果与前台操作 ticket 继续使用原互斥快照；后台线程不访问控件，也不更改后台同步的提示策略。
取消或网络变化会终止在途响应；DNS 调用仍受 lwIP 自身超时约束，停止不会强行释放其调用栈。

NTP 是独立网络订阅者，默认阿里云。每次有效网络代次最多三次尝试，失败间隔 30 秒，响应等待 5 秒。
成功后写 RTC，断线或网络切换后不提交旧请求结果。天气和 NTP 不相互占用通知回调槽。

## 更新事务

用户从“应用安装”选择目录包；首次安装选择内部存储或 TF 卡，同 ID 的更新沿用原安装位置。
相同版本仅允许配套固件 `build_id` 改变后的重新构建；相同版本和相同配置、降级、类型变化均拒绝。
更新前后 `data_version` 必须相同，不自动猜测数据迁移格式。卸载后重装时应用自行校验保留记录的版本。

安装准备阶段先请求页面退出及后台停止，最多等待 35 秒；超时返回“应用仍在使用，请重试”。
超时不修改应用文件，不强行回收模块；任务最终退出后可重新启动旧版本。
完整天气包与其他后台模块使用同一停止协议。
类型转换仅允许已知的旧天气资源包版本 1 升级为天气模块包版本 2 或更高版本，仍要求数据版本一致。

| 持久阶段 | 操作与恢复 |
|---|---|
| COPY | 复制至目标卷的 `.app-install`；恢复时丢弃未提交暂存目录，保留旧版本 |
| PUBLISH | 完整校验后将旧目录改名 `.app-old`，将暂存目录发布到 `apps/<id>`；中断后按目录状态继续或恢复旧版本 |
| COMMIT | 新目录已发布，清理旧目录及 `cache/<id>`；清理中断可以继续 |
| REMOVE | 将已安装目录改名 `.app-remove` |
| REMOVED | 清理移除目录及缓存；中断后继续清理 |

内部安装日志位于 `/flash/system/app-transaction.bin`，使用带 CRC 的临时文件写入、fsync 和 LittleFS 同卷 rename。
TF 卡的暂存、旧包及日志位于 `/sdcard/.epd/`，发布到同卷的 `apps/<id>`。
FAT 日志逐条追加带 CRC 的阶段记录并 fsync；恢复读取最后一条完整记录，后续写入覆盖未完成的尾记录，
不依赖 FAT 对已有文件的覆盖式 rename。FAT 自身的断电一致性不等同于 LittleFS。

安装、更新和卸载事务均保留对应卷的 `data/<id>`。更换安装位置的数据迁移在应用停止后单独完成：
目标已有数据时不覆盖，目标为空时先复制核对，再发布目录并清理源；可重建缓存不迁移。
复制失败或拔卡不发布尚未校验的包；恢复失败时保留日志和目录，
禁止从相应存储装载应用，不格式化存储。插卡恢复在后台执行，用户确认加载后才迁移数据、发布入口并启动后台应用。
拔卡时 UI 同时推进安装准备和服务退出，等安装线程关闭文件后才确认允许卸载文件系统。

运行模块及服务绑定原安装卷与插卡会话。拔卡立即使旧会话无效，迟到请求不转向下一张卡。
释放等待超过 35 秒时保留未结束模块并隔离 TF 卡；在 UI 回调能够返回的前提下，允许内置页面继续使用，不强制卸载仍在执行的代码。
SDK 的 FAT 关闭失败可能遗留文件句柄；平台检测到占用时不强制卸载，也不挂载新卡。原调用者无法清理的句柄需要重启恢复。
SD 控制器请求等待超过 10 秒后禁用卡至重启。运行步骤和验证边界见
[应用开发](APPLICATION_DEVELOPMENT.md)及[本轮实施清单](PORTABLE_APPS_TODO.md)。

## 上板检查

1. PAN 获得 IP 后，天气和 NTP 同时收到事件；断开重连能再次同步，离线不循环发请求。
2. 保持天气页面关闭半小时，检查静默同步和缓存；快速进入退出天气页不新增业务线程。
3. 安装 hello，返回主页后后台仍在；网络变化产生一次对应代次日志，不重复重绘页面。
4. 更新/卸载运行中的 hello，确认先退出页面、停止后台，再替换/移除目录；重复安装卸载检查内存。
5. 在复制、旧目录改名、新目录发布及清理阶段分别断电，重启后确认目录完整、旧数据仍在。
6. 安装过程中拔卡，确认失败后仍能运行旧版本，再插卡可以重试。
7. 选择 WiFi 但没有 WiFi 驱动时保持离线；切回 PAN 恢复。双网卡路由和 DNS 切换需接入 WiFi 硬件后验证。

构建通过仅验证配置、编译和链接；以上联网时序、停止并发、掉电恢复及运行内存需上板验证。
