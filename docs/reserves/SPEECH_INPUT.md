# 阿里云语音输入技术储备

## 目的与状态

语音输入拟作为平台按需服务，为搜索、查词和笔记等输入框提供文字。SF32LB57G 负责采音、必要的前处理、加密传输和结果显示，识别模型在阿里云运行。采用用户主动开始和结束的近距离录入，允许一次输入包含多句话。

当前没有接入语音输入服务。本板麦克风接口、双通道同步、云端联调、识别准确率和资源用量均待确认。常驻唤醒、语音对话、语音合成及本地完整识别模型不在该方案范围内。

## 组件和数据所有权

板级采音适配负责实际麦克风、采样时钟、DMA 和块序号；音频前处理负责将有效通道转换成待识别单声道。阿里云协议组件组织任务和句子事件，不持有页面。平台语音服务管理独占会话、队列、凭证、传输和结果快照；UI 适配显示草稿并在确认后写回当前输入目标。

动态应用通过开始、停止、取消及取结果操作使用服务，具体 ABI 在实现时确定。会话绑定应用实例和输入目标代次，后台不持有可卸载模块的裸回调或控件指针。一次只允许一项活动录音，第二个输入请求返回忙状态，不抢占麦克风。

采集回调只交付音频块和通知线程，不执行网络、JSON 或 LVGL 操作。DMA 缓冲按实际驱动确认内存区域、对齐和缓存维护；一般排队数据可以使用平台动态分配。服务拥有音频块，处理和发送结束后归还，UI 仅持有复制后的 UTF-8 文字。

## 采音和前处理

先根据原理图及实装器件确定模拟、PDM 或 I2S 接口，检查供电、通道排列和同步采样。取得双通道原始录音后，确认有效声道、削顶、丢帧及增益差异，再评估 SDK 算法对当前芯片和麦克风布置的适用性。

以同一录音分别生成有效单麦基线和双麦处理结果，交给同一云端模型比较文字错误。双麦不直接求平均；降噪、增益和利用播放参考消除回声的 AEC 仅在对应场景且测出收益后启用。本地语音活动检测可辅助状态，不通过停止发送静音片段代替云端断句。

拟采用 16 kHz、16 位、单声道 PCM 上传，数据不为每片追加 WAV 头。原始上传速率为 `16000 × 2 = 32000` 字节/秒；100 ms 分片为 3200 字节；同采样率双通道采集为 64000 字节/秒。允许积压 T 秒时，单声道队列至少需要 `32000 × T` 字节，另加协议、线程栈、算法和对齐开销。

T 由允许延迟及实测网络抖动确定。队列满或分配失败时终止本次输入并提示，不能丢弃中间音频后继续把结果当成完整录入，也不无限积压。

## 云端任务与文字合并

协议储备采用 NLS 实时语音识别 `SpeechTranscriber`，通过加密 WebSocket（WSS）连接。项目 Appkey、地域、模型和临时 Token 配套配置；实际语言能力取决于云端模型，不能仅凭客户端语言字段承诺英文或混说效果。

```text
空闲 → 准备网络与凭证 → 建立连接并启动任务 → 就绪后采音和识别
     → 停止采音、发完队列 → 等待任务完成 → 用户确认文字

取消、输入目标销毁或不可恢复错误 → 停止采音和传输 → 释放会话
```

一个任务使用同一 `task_id`，控制消息使用独立 `message_id`。发送 `StartTranscription` 并收到 `TranscriptionStarted` 后上传二进制音频；用户停止后发完已经采集的块，再发 `StopTranscription`，等待 `TranscriptionCompleted`。服务就绪之前界面显示准备状态，尚不宣称开始收音。

`TranscriptionResultChanged` 更新当前句子草稿，`SentenceEnd` 固定对应句子的最终文字。服务按任务和句子 `index` 管理内容：中间结果替换同一句旧草稿，重复最终事件不重复追加。结果快照含会话标识、修订号、状态和复制后的文字。异常断开时，已完成句子与未完成草稿分别呈现，不自动把草稿作为确认内容。

用户确认前，原输入框保持原文字；确认时由 UI 再次核对目标代次及插入位置。打开语音面板造成原页面暂停时可以继续录音，目标销毁、应用退出或卸载时才使绑定失效。取消立即使绑定失效，停止则等待最终结果，两种操作具有不同语义。

墨水屏只更新变化的文字和状态，允许合并频繁的中间结果，不能丢最终文字。音频持续处理不等待面板完成，不通过加载动画或周期刷屏维持录音状态。

## 传输、凭证与持久化

SDK WebSocket 使用 lwIP 回调，需按 TCP/IP 线程规则调用。现有 [wsock_init()](../../SiFli-SDK/rtos/rtthread/components/net/lwip/lwip-2.1.2/src/apps/websocket/websocket_client.c) 向 TLS 配置传入空 CA，[ALTCP TLS](../../SiFli-SDK/rtos/rtthread/components/net/lwip/lwip-2.1.2/src/apps/altcp_tls/altcp_tls_mbedtls.c)使用可选验证模式。接入必须补齐可信证书、强制验证、域名校验和服务器名称，公共 HTTPS 的检查不会自动应用到另一套连接。

传输适配还需确认客户端帧掩码、分片、Ping/Pong、部分发送、关闭和分配失败处理。发送和接收同时推进，网络代次变化使旧任务结束，不能把 PAN/Wi-Fi 切换当作同一连接无缝续传。取消先停止新采样及提交，再结束传输；回调不再引用会话后释放缓冲。

正式部署由自有凭证服务鉴别设备或用户，服务端保存 AccessKey 并取得 NLS Token，向设备返回临时 Token、过期时间和项目配置。设备直连阿里云发送音频，自有服务默认不转发音频。Token 在有效期内复用，以返回的过期时间为准；长期密钥不放入固件、应用包或卡内配置。

正常工作不保存音频和识别全文日志，临时 Token 默认只在内存保存。公开接口只向动态应用交付文字结果，不交付云凭证。测试录音另行管理；产品启用前明确音频发送目的地、云账号、模型、费用承担及保留方式。

## 实施与验证入口

实施顺序为：确认本板采音 → 用真实录音打通云端协议 → 补齐可信 WSS 与取消 → 接入有容量边界的音频队列 → 实现句子合并和 UI 绑定 → 评估单麦/双麦效果 → 联合应用退出、网络变化和显示验证。尚没有项目级语音构建选项或可运行的端到端测试入口。

准确率使用固定参考文本计算字符错误率，即替换、删除和插入字符数之和除以参考字符数，明确标点、数字及大小写规则。延迟分别测量点击到就绪、首个采样到首次出字、停止到最终结果；同时记录样本数、分布、音频块连续性和队列峰值。当前不承诺准确率百分比、固定响应时间或双麦一定优于单麦。

部署前仍需确定真实麦克风通路、主要语种、说话距离、云端项目及设备鉴别方式。协议参数沿用实时识别设计，正式联调时核对服务当时的接口版本。

协议资料入口：[实时识别参数](https://help.aliyun.com/zh/isi/user-guide/api-reference)、[WebSocket 指令与事件](https://help.aliyun.com/zh/isi/user-guide/websocket)、[临时 Token 获取](https://help.aliyun.com/zh/isi/user-guide/obtain-an-access-token-1/)。
