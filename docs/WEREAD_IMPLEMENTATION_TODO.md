# 微信读书实施清单

## 接入结构

微信读书作为独立 `weread.so` 应用运行，使用平台网络、存储、后台服务和 app_fwk。章节协议留在应用内，HTTP 传输和阅读显示使用共享源码组件。应用不依赖安装 `books.so`，也不自建页面导航栈。

## 验收边界

- 手机扫码确认登录并显示可能出现的双重验证码；设备负责验证码输入、书架、目录及章节读取。
- 使用服务器正常向当前账号提供的内容。双重验证完成后才建立登录会话；试读或权限不足均明确返回，不作为成功正文缓存。
- 已完整缓存的目录和章节可离线打开；内容更新不会继续使用旧分页偏移。
- 页面返回、账号切换、应用停止、网络切换和拔卡后，不发布过期结果，不强杀仍持有资源的线程。
- 阅读位置按账号、bookId、chapterUid 和内容位置保存，不依赖书架序号或页码。
- 不增加云端阅读进度同步、全书批量下载或新的屏幕驱动行为。

### 构建产物

| 板型 | 目录 |
| --- | --- |
| DPI | `project/build_dpi-hdk_lb57gyd7n6_epd_hcpu/` |
| LCD 载板 | `project/build_sf32lb57-lcd-gyd7n6_epd_hcpu/` |

两个目录已有 `main.elf`、固件镜像、`fs_root.bin` 和 `app-resources/{weather,books,gallery,words,weread}/`。页面导航修复只重新构建 `app-resources/weread/`，应用版本为 3，数据版本仍为 1。两板的 `weread.so` 均为 448140 字节，清单记录的加载大小为 449844 字节；加载大小不包含运行时网络、文档、字体和图片分配。

独立构建完成了 182 个导入符号检查；两板 `main.elf` 在构建前后的 SHA-256 完全一致。编译仍有工具链 `libgcc` 的 `wchar_t` 大小不一致链接警告，未为页面导航修复修改编译 ABI。

构建保留原有 `PREINSTALL=weather,books`，因此 `fs_root.bin` 预装天气和书架，微信读书作为独立安装包输出。需要工厂预装微信读书时，使用[应用说明](../modules/weread/README.md)中的三应用预装命令。本次没有烧录、提交或推送，也没有为此次移植修改 SDK 源码、波形和扫描时序。
