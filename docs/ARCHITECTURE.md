# 墨水屏应用平台架构

## 1. 平台定位

平台为 SF32LB57 提供显示、存储、联网、应用安装和动态模块运行能力。参考设计选择板级配置、公共组件和预装应用；天气、阅读、图库、单词及微信读书业务位于独立模块中。平台可以不安装任何动态应用而运行内置桌面、文件管理和设置。

当前参考硬件使用 E0470A03 墨水屏。DPI-HDK 与 LCD DevKit 是不同载板配置，LCD DevKit 配置仍驱动墨水屏。构建、安装包和烧录脚本按板型分别输出，详见 [构建说明](BUILDING.md)。

## 2. 分层与依赖

```text
参考设计：板型、组件清单、应用构建列表、预装列表
 ├─ 动态应用：weather / books / gallery / words / weread / board
 │    └─ 公共源码组件：HTTP、文档阅读视图、图片解码
 ├─ 平台公共服务：网络、时间、存储、字体、摘要、内容交接
 ├─ 应用运行支持：目录、安装事务、兼容检查、受管服务、恢复入口
 └─ SiFli SDK：app_fwk、RT-Thread、LVGL V9、DFS、显示及硬件驱动
```

| 代码位置 | 职责 | 依赖方向 |
| --- | --- | --- |
| `project/`、`boards/` | 产品构建配置、分区和载板适配 | 选择 SDK 与平台能力 |
| `src/boards/` | 存储板级适配、输入、电池等公共设备 | 依赖 SDK 和组件，不依赖动态应用 |
| `src/services/` | 安装卷、文件持久化、网络、时间、受管服务 | 向 UI 和应用提供数据与同步接口 |
| `src/ui/platform/` | 模块目录、加载与安装、公共 UI、刷新语义、内容交接 | 使用 SDK，不执行应用私有业务规则 |
| `src/ui/apps/` | 必须随固件存在的文件管理、设置等页面 | 使用平台服务 |
| `modules/common/` | 多应用共享、随使用者构建的源码组件 | 不依赖 Launcher 或某个应用的全局对象 |
| `modules/<id>/` | 独立应用的页面、业务、资源与数据格式 | 使用公开头文件和模块内组件 |
| `tools/` | 构建衔接、开发包导出、资源准备、验证和发布目录 | 运行在电脑端 |

公共源码组件与主固件服务的交付方式不同：前者编入使用该组件的模块，后者由固件提供并通过导出符号调用。共享目录本身不代表已经发布为 SF-PKG 包。

## 3. 启动与应用运行

`src/main.c` 初始化 LVGL、平台内存、文件系统、安装恢复、网络、蓝牙、设置和时间服务，随后启动 UI。主线程调用 `ui_app_process()`、`lv_timer_handler()`，并结合受管服务的下一工作期限让出处理器。

应用与页面状态由 SDK `app_fwk` 管理。`ui_navigation.c` 是内置页面路由适配，不维护另一套导航栈。`app_catalog.c` 向 SDK 注册动态模块加载和卸载入口。

动态应用启动顺序为：

1. 确认动态执行未被恢复模式禁止，安装卷和存储会话可用。
2. 读取清单，检查包格式、固件兼容标识、文件摘要和 ELF 格式。
3. 调用 SDK 模块加载器，将代码、数据和重定位结果装入内存。
4. 校验应用入口和描述符，必要时启动受管后台服务。
5. app_fwk 调用 `app_main()`，再按状态调度页面生命周期。

兼容检查放在模块初始化前，因为 SDK 的模块加载过程可能调用 `module_init`。桌面枚举名称和图标只读安装清单，不加载模块。

### 3.1 页面与对象所有权

| 生命周期 | 页面职责 |
| --- | --- |
| `ONSTART` | 使用框架分配的页面内存和 screen 创建控件；初始化自有资源 |
| `ONRESUME` | 读取最新业务快照，恢复选择和滚动位置，恢复前台更新 |
| `ONPAUSE` | 保存必要状态，暂停页面定时器和前台专属工作 |
| `ONSTOP` | 删除自建定时器，解除订阅，释放自有句柄和缓冲；清空外部页面引用 |

框架负责删除 screen 和页面内存。页面不能重复释放这些对象。退到后台与退出页面不同：暂停页面可能继续保留控件，而已经停止的页面不能接收旧异步结果。

### 3.2 后台服务

`app_service.c` 保留模块引用，管理工作线程、网络订阅、串口命令及 UI 阶段回调。页面退出不会直接停止长期业务。卸载、更新和介质移除先请求服务停止，等工作线程、在途命令和 UI 清理完成后才释放模块。

工作线程发布数据副本，不操作 LVGL。`ui_process` 在主线程执行，一次只完成有界工作；需要继续时声明下一期限。阅读预排版和字体准备不能长期占用 UI 或抬高后台线程优先级来挤占显示任务。

应用摘要保存在固件服务记录中。消费者按服务 ID 读取副本并观察变更序号，不持有应用字符串或回调。相同文字重复发布不产生新序号；停止服务后不再向消费者返回其摘要。

## 4. 存储与安装

内部 NOR 文件系统使用 LittleFS，挂载 `/flash`；TF 使用 FatFs，挂载 `/sdcard`。程序、业务数据和缓存跟随应用安装卷，路径通过 `storage_app_path()` 生成。

| 内容 | 内部存储 | TF 卡 |
| --- | --- | --- |
| 已安装程序和资源 | `/flash/apps/<id>` | `/sdcard/.epd/apps/<id>` |
| 持久化数据 | `/flash/data/<id>` | `/sdcard/.epd/data/<id>` |
| 可重建缓存 | `/flash/cache/<id>` | `/sdcard/.epd/cache/<id>` |

安装源目录与安装目标不同。TF 上的 `apps/<id>` 通常用于交付安装包，安装器将其复制到所选安装位置。安装以暂存目录、校验和事务记录发布，更新保留应用数据。

模块装载时绑定安装卷和存储会话。TF 拔出后，旧会话失效；插入另一张卡不会使旧句柄恢复有效。存储协调器停止动态页面和受管服务，等待访问者释放后再卸载。无法完成退出时保留代码引用，不强杀正在执行模块的线程。具体流程见 [应用生命周期](APPLICATION_LIFECYCLE.md) 和 [随卡应用](PORTABLE_APPS_TODO.md)。

平台系统设置、恢复模式和内部字体导入不随某个动态应用卸载。当前分区以板型的 `ptab.json` 为准，容量与迁移说明见 [存储迁移](STORAGE_MIGRATION.md)。

## 5. 网络与内容交接

`network.c` 将当前可用网络及其变化作为快照和 RT-Thread 事件提供给多个使用者。订阅者注销完成后才能释放事件对象。应用不直接依赖 PAN 状态；未来 Wi-Fi 适配器登记网卡和 DNS 后可复用同一接口。当前选择项存在不等于已经具备 Wi-Fi 驱动。

应用通过清单声明能够打开的文件类型。文件管理器发现处理者并发起内容交接，接收应用负责解释内容、保存业务状态和处理文件不可用。交接不传递文件句柄或跨模块控件地址。协议及接口见 [内容处理](CONTENT_HANDLERS.md)。

## 6. 显示与字体

平台使用 LVGL V9 和 SDK EPIC 绘图实现。`epd_refresh.c` 观察 app_fwk 页面生命周期和 LVGL 刷新提交：切页的第一帧请求全刷；同页内容更新保留全刷周期；仅状态栏更新走不累计周期的局刷路径。

驱动负责波形、温区、面板扫描和刷新后断电。业务应用创建控件或更新数据，不直接操作面板电源、扫描时钟或波形。`epd_app_text()` 保存原始业务文字用于变化判断，避免把 LVGL 省略后的显示文字误认为业务变化。

内置 MiSans 字体以压缩资源保存，启动解压至 RAM1，字体数据与字形像素缓存是不同对象。字体像素仍按实际字形和字号准备与淘汰，完整 TTF 入内存并不意味着所有字号的像素已经生成。

## 7. 兼容、诊断与恢复

每套固件生成 `app-profile.json`。配置标识覆盖 SDK 状态、工具链、最终配置和公共接口。当前采用精确配套，不承诺跨固件任意二进制兼容。安装包版本、数据版本、包格式和接口版本分别管理。

动态模块与主固件共享地址空间，未提供进程隔离。模块错误可能导致整个设备异常。精确构建符号、模块装载地址与崩溃现场用于定位；恢复模式在重启后禁止动态执行，使内置管理功能可以用于处理问题应用。恢复模式不能挽救正在运行的任意死循环。详见 [故障取证](DYNAMIC_APP_DEBUGGING.md) 与 [恢复操作](RECOVERY.md)。
