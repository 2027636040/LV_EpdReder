# 应用平台与存储实施方案

## 第一阶段结论

平台复用当前 SiFli SDK 的 app_fwk、RT-Thread 动态模块、DFS、LittleFS、FatFs 和 EZIP。
SDK 固定为 `a25ebccdb986a98070287cf1701dc5adb10a265d`，保留已有本地修复。
应用与页面导航只有 app_fwk 一个权威实现；安装器负责文件发布，模块装载器负责代码装载，
后台服务管理与页面生命周期分离。原生模块暂不签名，不提供进程隔离。

既定产品方向已足够启动实现。以下事项不需要重新选择：

- NOR 使用 LittleFS，TF 卡使用 FatFs，分别挂载 `/flash`、`/sdcard`。
- 应用目录不占用专属物理分区；程序、资源、持久化数据和缓存分开。
- 入口图标是安装包中的独立 EZIP 文件；Launcher 读取清单和图标，不装载应用代码。
- 资源区 8 MiB、ACPU 保留区 128 KiB，不再预留独立 OTA 程序区。
- 升级包可存放在文件系统中；独立升级程序尚未实现。
- 保留现有 UI、触摸操作和墨水屏刷新策略；不在本轮改变扫描、波形或供电控制。

波形区暂保留 256 KiB。缩减波形区、扩大主程序区、清空设备数据均不作为默认操作。
后续编译如证明主程序必须扩容，先报告实际缺口和对文件系统容量的影响，再确定容量调整。
分区升级前需要导出设备旧数据；没有有效备份时不执行破坏旧布局的烧录。

## 包格式与兼容性

沿用目录式安装包，避免为第一版新增压缩容器和解包依赖：

```text
/sdcard/apps/hello/
    app.json
    files.sha256
    hello.so
    icon.ezip
    res/...
```

`app.json` 是 UTF-8 JSON，读取缓冲按文件实际大小申请；包构建工具生成兼容性与文件校验字段：

```json
{
  "package_format": 1,
  "abi": 1,
  "id": "hello",
  "version": 1,
  "name": "触摸示例",
  "build_id": "<配套固件兼容配置的 SHA-256>",
  "files_sha256": "<files.sha256 文件的 SHA-256>",
  "settings": false,
  "background": false,
  "data_version": 1,
  "icon": "icon.ezip",
  "load_bytes": 4096
}
```

- `package_format` 表示安装包结构版本；`abi` 表示平台导出接口版本，二者与应用发布版本分离。
- `version` 是递增的正整数，供更新比较使用；`data_version` 是应用持久化格式版本。
- ID 受当前 `RT_NAME_MAX=8` 限制，使用 1～7 个小写字母、数字或下划线，不能占用内置 ID。
- 名称最多 47 个 UTF-8 字节；程序固定为 `<id>.so`，不能通过清单指定任意执行路径。
- `build_id` 来自 SDK 提交及本地差异、实际 RT/LVGL 配置、工具链和平台公开接口。
  开发阶段采用精确配置匹配；改变这些输入后重新构建模块，不宣称任意固件间二进制兼容。
- `files.sha256` 使用 `64位小写十六进制摘要 + 两个空格 + 相对路径 + 换行`。
  路径使用 `/`，禁止绝对路径、空路径段、`.`、`..`、反斜杠和控制字符，最多八层。
  文件索引覆盖程序、图标和私有资源，不包含自身及 `app.json`。
- 安装前、复制到暂存目录后校验完整文件索引；启动前校验清单兼容性、索引摘要及程序摘要，
  然后才调用 `dlopen`。校验只能发现不兼容或文件损坏，不能认证发布者。
- `icon` 可省略并使用平台默认入口图标；存在时必须随包安装且在索引中。
- `load_bytes` 由 ELF 的 PT_LOAD 段计算，不等于 `.so` 文件大小，也不包含运行时堆、栈和图像缓存。
- `background=true` 启用受管常驻任务，模块必须导出 `epd_app_background`；更新/卸载等待任务主动退出后才释放代码。

模块保留 `epd_app_info`、`app_main` 两个现有入口，并嵌入编译时兼容配置标识。
SDK 的 `dlopen` 内部可能先执行 `module_init`，因此不能只在 `dlsym(epd_app_info)` 后检查兼容性。
旧版简化清单仍可被应用管理读取和卸载，但必须重新打包后才能通过新装载检查。

## 平台接口与责任边界

| 功能 | 平台负责 | 应用负责 |
|---|---|---|
| 导航 | 直接提供 SDK app_fwk 接口和统一返回控件 | 注册根页/子页，保存恢复业务状态 |
| 页面生命周期 | 框架 screen 和页面内存 | ONPAUSE 停止页面更新，ONSTOP 释放自有资源 |
| 网络 | PAN/WiFi 路由选择、网络就绪状态、NTP、可注销事件订阅 | 发起业务请求，读取结果快照，不依赖底层来源 |
| 后台任务 | 在卸载前停止任务、取消订阅并等待在途回调结束 | 不把长期任务绑在页面 ONSTART/ONSTOP 上 |
| 文件系统 | 挂载、热插拔、受锁保护的短时文件操作、目录构造 | 文件格式版本、数据读写、关闭自有句柄 |
| 字体与图像 | 公共字体、EZIP 解码、公共图标 | 私有资源按需加载，保持缓冲至 GPU 使用完成 |
| 应用设置 | 清单枚举与 `page=settings` Intent | 自己的设置页及数据迁移 |
| UI 数据发布 | UI 线程消费事件/快照，只更新变化控件 | 后台线程不直接访问 LVGL 控件 |

公共接口按实际使用逐步扩展，不批量导出业务私有函数，也不复制 SDK 已有页面栈。
PAN 单回调槽已经替换为统一网络事件订阅；注销返回后才能销毁接收事件对象。
后台任务结束之前保留模块引用；页面关闭不等于后台模块可以卸载。
SDK 的模块对象清理继续复用，但不能代替外部服务持有的函数指针和事件订阅的清理。

## 文件目录与更新规则

```text
/flash/apps/<id>/        已发布的程序与只读资源
/flash/data/<id>/        应用持久化数据
/flash/cache/<id>/       可重建缓存
/flash/system/          系统设置、安装事务状态
/flash/fonts/           从 TF 导入并确认写入成功的字体
/flash/update/          OTA 更新包
```

目录 API 根据应用 ID 和资源相对路径生成完整路径，不向每个应用暴露分区地址。
这些目录是原生应用的职责约定，不是硬件或进程级访问隔离。
新版本先完整复制、校验，再发布；更新保留 `data/<id>`，清理可重建缓存。
卸载默认保留持久化数据；单独的清除数据操作才删除该目录。
更新必须先让运行模块停止并释放资源引用；不能在模块仍执行时替换或删除其文件。
事务恢复只修复已记录的安装状态，不能因挂载失败自动格式化。

天气配置、天气缓存和系统设置由当前专用分区迁入目录。
旧记录导出与恢复必须保留版本、校验和以及最近阅读位置；TF 外置字体先复制至内部存储再应用。
后台天气仍保持 30 分钟同步、所选网络就绪后同步、失败后 5 秒受控重试及现有读写锁。

## Flash 预算

第一阶段修改前的 `ER_IROM1.bin` 为 2,082,080 字节，2 MiB 主程序区剩 15,072 字节。
接入包校验后的镜像为 2,084,624 字节，剩 12,528 字节；增加 2,544 字节。
`ER_IROM2.bin` 为 4,085,246 字节，放入 5 MiB 资源区后剩 1,157,634 字节。
波形二进制为 223,240 字节。上述镜像大小是第一阶段记录；完整 MiSans 替换内置字体后，
当前资源区扩至 8 MiB，主程序仍为 2 MiB：

| 分区 | Flash 内偏移 | 容量 | 处理 |
|---|---:|---:|---|
| 启动表、校准及 Bootloader | 0x000000 | 128 KiB | 保留启动必要区域 |
| 主程序 | 0x020000 | 2 MiB | 每阶段编译检查，不默认扩容 |
| 固件公共资源 | 0x220000 | 8 MiB | 内置完整 MiSans，应用私有资源放入安装包 |
| ACPU | 0xA20000 | 128 KiB | 保留空间，不启用协处理器 |
| BLE KVDB | 0xA40000 | 16 KiB | 保留现有蓝牙初始化机制 |
| 波形 | 0xA44000 | 256 KiB | 保持原内容 |
| 内部 LittleFS | 0xA84000 | 5,616 KiB | 使用全部剩余空间 |

内部文件系统原始容量为 5.484375 MiB，实际可用空间扣除文件系统元数据和已安装内容。
回收旧 DFU 程序/下载/KVDB 区、天气/设置专用区及未分配间隙；BLE 数据在迁移时单独保留。
OTA 包、应用新旧版本、字体和用户数据共享文件系统，操作前按当前可用空间计算需求。
原独立 OTA 程序预留的 2 MiB 与内部文件系统缩减的 1 MiB 均分配给公共资源区。

## RAM 预算

以下数字来自当前链接图和构建配置，不是运行峰值测量：

| 区域 | 字节数 | 说明 |
|---|---:|---|
| PSRAM 物理容量 | 16,777,216 | 16 MiB |
| SDK 图像/模块共享池 | 6,291,456 | 模块由 `app_cache_alloc(CACHE_PSRAM)` 分配 |
| Tiny TTF 缓存池 | 262,144 | 与上项一起占据 0x640000 保留区 |
| LVGL 私有堆 | 2,097,152 | 页面、部分图像解码缓冲等 |
| LVGL 显示缓冲 | 1,772,928 | 链接图 0x1B0D80 |
| 墨水屏混合灰度缓冲 | 831,744 | 链接图 0xCB100 |
| 静态 PSRAM 区末尾之后 | 5,521,792 | 不等于现有分配器可立即使用的空闲堆 |

模块装载峰值至少包含 `.so` 临时文件镜像、PT_LOAD 地址跨度、符号表/名称和装载管理对象；
运行时再加应用堆、任务栈、资源缓存。不能只用文件大小批准应用。
安装复制缓冲继续使用 4 KiB；文件摘要分块计算，不全量读入天气资源库。
入口只保持当前页所需图标，天气大图和小图按需解码，不把整个图标库解压到 RAM。
LittleFS 文件不能假定连续映射到 NOR；EZIP 文件解码须按 SDK 文件解码路径持有压缩数据缓冲。
共享池可能回退系统 SRAM，不具备强制应用内存配额。后台服务记录按需申请，线程栈大小和优先级仍有限定，
并回收任务创建失败时的申请。SDK ELF 装载器的装载区、符号表和符号名分配失败返回错误，统一清理未完成的模块。
装载前不设置固定内存准入门槛；ELF 文件大小与 PT_LOAD 跨度之和仅用于辅助库装载前的缓存回收提示，能否装载由实际分配结果决定。

4. **更新与后台生命周期**：版本更新、事务恢复、模块引用及取消/等待语义、网络多订阅者。
5. **天气参考应用**：界面与后台服务整体动态化，复用现有天气解析、持久化、网络和同步逻辑。
6. **验证**：编译检查容量；上板检查安装/返回/卸载、热插拔、中断恢复、天气后台更新和重复加载内存。

完整 OTA 更新器、PM、相册解码扩展仍按各自技术储备实施，不混入本轮基础改造。
