# 参考组合与应用发布

## 1. 交付单位

平台固件与动态应用分别构建。一个可复现的发行组合由板型、平台配置、SDK 与组件版本、应用选择和对应构建产物组成。固件目录 `project/build_<board>/` 是烧录入口；`app-resources/<id>/` 是完整应用包；`debug-artifacts/` 是配套诊断符号。

应用源码、私有资源和正常构建使用的预生成数据纳入版本管理。调试符号与二进制产物由构建产生，不以开发者工作目录中未记录的输入作为发布依赖。

## 2. 参考组合

以下组合复用同一平台与同一套应用源码：

| 组合 | `APPS` | `PREINSTALL` | 使用方式 |
| --- | --- | --- | --- |
| 空平台 | 不传 | 不传 | 只保留内置桌面、文件和设置 |
| 阅读终端 | `weather,books,gallery,weread` | `weather,books` | 其余应用按需安装 |
| 单词学习终端 | `words` | 不传 | 全量词库随包分发，使用 TF 安装空间 |
| 信息看板 | `board,weather` | `board,weather` | 模板引用天气摘要；天气未安装时显示模板空状态 |

预装是否能够放入内部文件系统，以制镜工具实际容量检查为准。完整单词库不默认塞入内部文件系统。

以 DPI-HDK 阅读组合为例：

```powershell
. .\SiFli-SDK\export.ps1
scons -C project --board=dpi-hdk_lb57gyd7n6_epd_hcpu APPS=weather,books,gallery,weread PREINSTALL=weather,books STORAGE_IMAGE=1 -j8
```

`STORAGE_IMAGE=1` 用于工厂初始化，会把文件系统镜像加入下载列表。正常保留用户数据的固件升级不使用此选项。LCD DevKit 则选择相应板型及 `--board_search_path=../boards`。

## 3. 发布目录生成

从已构建包生成固件专用目录：

```powershell
python tools/release_catalog.py --firmware project/build_dpi-hdk_lb57gyd7n6_epd_hcpu --apps weather,books,gallery,words,weread,board
```

输出 `app-catalogue.json` 包含板型、兼容标识、应用版本、数据版本、完整包字节数、清单摘要及随包许可证文件位置。生成前校验设备要求的索引格式，流式验证每个负载摘要，并确认声明的图标和私有库在包内；拒绝不匹配固件、额外旧文件、缺失文件、链接目录和损坏包。先结束构建再生成目录，生成期间保持包目录不变。

省略 `--apps` 时检查目录中所有已有包，包括以前的输出。因此旧包没有配套更新会明确失败，而不会被默认为兼容。目录只引用相对路径；发布时保持整个 `app-resources/<id>/` 的内容不变。目录摘要用于发现内容变化，不认证发布者身份。

## 4. 应用作者交付内容

一个应用发布应同时具备：

1. 源码和许可证、可重复执行的构建说明。
2. 针对明确平台配置构建的完整目录包。
3. 数据格式版本、迁移方法及安装位置规则。
4. 对应 `.nostrip` 调试符号和 GNU build-id 记录。
5. 页面、存储、后台停止与网络断开等测试结果。
6. 实际运行验证的板型及限制。

安装版本号在业务功能或包内容更新时递增；同一版本为新固件重新构建使用新的兼容标识。代码版本、数据版本、兼容标识和精确调试 build-id 分别表达不同含义。

## 5. 发布检查

- 两种目标板分别构建和检查，不混用应用包、启动镜像与主程序。
- 用独立开发包在仓库外构建示例，确认没有残留本机源码依赖。
- 对所选应用生成发布目录，确认清单、资源摘要与固件标识匹配。
- 工厂初始化验证预装入口；普通升级验证用户数据保留。
- 上板完成进入返回、后台更新、热插拔及恢复模式检查。
- 保存对应诊断符号，保留已发布版本，之后的重新编译产物不替代原故障版本。

当前工具负责生成可托管的目录文件，没有部署在线应用商店，也没有替发布者上传组件或二进制包。
