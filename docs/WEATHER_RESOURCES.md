# 天气应用资源

## 目录与生成

天气界面、设置与后台服务已迁入 `modules/weather`，编译为 `weather.so`。
天气程序和私有图片一起安装到用户选择的内部存储或 TF 卡，不再作为内置天气应用或公共资源镜像的一部分。
以下以内置 NOR 的文件系统路径为例；安装到 TF 卡时根目录为 `/sdcard/.epd/apps/weather`，资源路径由平台解析。
资源使用当前 SDK 的 EZIP 工具，从 `assets/ezip/` 中的 PNG 生成，保持原尺寸、灰度和透明度。

```text
/flash/apps/weather/
    app.json
    files.sha256
    weather.so
    icon.ezip
    res/
        w100_160.ezip
        w100_48.ezip
        ...
        w999_160.ezip
        w999_48.ezip
        ui_icon_location.ezip
        ui_icon_humidity.ezip
        ...
```

共 150 个 EZIP 文件：70 种天气各有 160×160、48×48 两个尺寸；
9 个位置/天气指标图标为 32×32；独立桌面入口为 80×80。
未知天气代码使用 999，单个天气图标缺失时尝试同尺寸 999。
没有资源时保留原布局，天气图像位置留空，桌面使用公共默认图标；不增加提示标签或定时重试。

当前包是版本 2 的动态模块包，`kind` 省略，声明 `settings: true` 和 `background: true`。
清单、固件配置标识、全部文件摘要、暂存复制和完整校验复用应用安装器。
未安装时没有天气入口、应用设置或后台服务；入口图标本身不触发装载，
声明后台任务才会由平台主动加载模块。原资源包版本 1 仅作为升级兼容对象保留识别。

## 部署

普通固件构建自动编译天气模块、核对外部符号并生成完整安装目录：

```text
project/build_dpi-hdk_lb57gyd7n6_epd_hcpu/app-resources/weather/
```

对于已经完成第二阶段分区迁移的设备：

1. 使用当前构建目录的原生下载脚本更新固件与公共资源。普通下载不会覆盖内部文件系统。
2. 将生成的完整 `weather` 目录复制到 TF 卡的 `apps/weather/`，不要只复制 `.so`、PNG 或部分 EZIP。
3. 在“设置 → 应用管理 → 应用安装”中安装“天气”。安装后启动后台任务，桌面出现天气入口，应用设置出现天气设置。
4. 已安装旧天气资源包版本 1 的设备可直接更新到完整模块包版本 2，保留 `/flash/data/weather`。
   只下载固件但不安装新包，不会自动补齐 `weather.so`，旧资源目录不会显示天气入口。

安装失败或复制时拔卡，不发布半成品目录。安装完成只发布目录变更序号，UI 线程在前台处理；
后台安装线程不操作控件。更新或卸载天气先退出页面、停止后台任务并等待在途调用结束，
再替换或删除程序与资源，清理可重建缓存，保留天气配置。卸载后主页不再显示该服务的旧摘要。
停止与事务规则见 [后台生命周期与网络](APPLICATION_LIFECYCLE.md)。

首次初始化使用 `STORAGE_IMAGE=1`，完整天气包随 LittleFS 镜像一起生成。
旧分区升级使用 `STORAGE_IMPORT=<备份目录>`，构建在临时目录中叠加天气包，
不修改原备份；备份里已有 `apps/weather` 时保留该目录，旧包需通过上述安装流程更新。
旧布局设备仍必须先完成 [存储迁移](STORAGE_MIGRATION.md)，不能直接烧录新布局。

## 运行时所有权

`platform/app_image.h` 提供 `epd_app_image_set()`、`epd_app_image_release()`，通过 `epd_app.h` 对模块公开。
应用先用 `storage_app_path()` 生成内部资源路径，再将路径交给图像控件：

```c
char path[96];
storage_app_path(path, sizeof(path), "hello", STORAGE_APP_CODE, "res/picture.ezip");
epd_app_image_set(image, path, NULL);
```

这些函数只在 UI 线程调用。底层复用 SDK LVGL V9 EZIP 解码器；LittleFS 不提供连续物理地址，
SDK 读入压缩数据，保持解码会话直到控件换图、页面暂停或控件销毁。
资源加载后按压缩字节数执行数据缓存写回，再由 EPIC/EZIP 读取。
释放前等待 GPU 绘制完成，并清除该图像的 LVGL 缓存引用；不等待或改变墨水屏供电时序。

相同文件不重复读入或重设控件源；天气数据变化只换发生变化的图标。
天气页同时持有当前大图、三天小图和九个信息图标，不加载整个图库。
桌面只加载当前页图标，不调用 `dlopen()`；换页释放离开当前页的文件图标。
天气页和桌面的 ONPAUSE 释放文件图像，ONRESUME 按当前数据恢复，LV_EVENT_DELETE 自动清理剩余引用。
普通静态公共图标仍直接使用只读资源描述符。所有页面继续关闭动画。

## 构建核对与上板验证

第三阶段已核对 150 个图像的 EZIP 负载与迁移前的 C 数组逐字节一致，
图像文件总计 135,914 字节。第五阶段额外包含 `weather.so`，不能再用原资源包体积作为完整包大小。
LittleFS 按块分配，实际磁盘占用大于文件长度合计。

上板检查：安装后桌面天气入口及所有天气图标正常；同步天气后只替换变化内容；
天气页与设置子页反复进入返回没有内存持续增长；关闭天气页后仍能后台同步并更新主页摘要；
拔 TF 卡后后台在存储重新就绪时重启，天气图标仍从内部存储读取；
同步期间更新/卸载能够等待任务退出，入口和设置随安装状态变化；重新安装可恢复配置；
资源文件校验失败时不发布目录。
编译及二进制比对不能代替硬件解码、热插拔和页面恢复验证。
