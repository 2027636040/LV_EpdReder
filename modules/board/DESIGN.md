# 看板实现设计

## 目的与设计取舍

`board.so` 让使用者通过配置组合文字卡片和平台摘要，作为不编写固件代码的创作入口。它同时验证应用无需修改 Launcher 就能消费天气等服务的公开摘要；不是新增一套任意脚本、控件和数据源都可执行的页面引擎。

配置先完整解析与验证，再创建控件；用户配置只有确实不存在才使用包内默认内容。这样错误配置会得到明确失败，不会被悄悄替换为一张看似加载成功的默认看板。未知字段拒绝是当前格式契约，不能通过生成尚不存在的字段获得新能力。

设备和电脑预览共用布局计算，目的是让配置边界与几何结果可检查；浏览器文字栅格与 LVGL 不同，因此不承诺像素一致，也不把该预览当作完整平台模拟器。需要真实字体、触摸、生命周期和刷新表现时仍以上板为准。

摘要只读取平台持有的文字副本及修订号，不运行另一应用的完整页面，不保留跨模块控件或裸回调。当前定时器只在前台检查含摘要的页面，内容不变就不触发更新；500 ms 是检查间隔，不是屏幕刷新周期。更丰富的数据类型、编辑器和远端整屏渲染仍需单独设计。

平台层取舍见[开发意图与设计决策](../../docs/DESIGN_INTENT.md)，配置格式与使用入口见[看板模板](../../docs/BOARD_TEMPLATES.md)。

## 配置与模型

`board_store.c` 在存储锁内使用 `storage_app_path()`、`storage_app_available()` 和 `storage_file_recover()` 读取配置。用户配置只有在打开失败且错误为文件不存在时才回退到安装包资源。读取按文件实际长度分配缓冲区，以 4096 字节为一次 I/O 的最大块大小；此块大小不是配置容量上限。读取中断、文件变长、卷失效和长度超出 `PTRDIFF_MAX` 都会结束加载并释放缓冲区、关闭文件。

`board_model.c` 调用平台已导出的 `cJSON_ParseWithOpts()`，要求完整解析输入。模型持有 cJSON 解析树，卡片字符串借用解析树中的字符串。模型及卡片节点通过调用方分配器分配，设备分配器使用 `epd_app_alloc(..., EPD_APP_PSRAM)`。cJSON 使用平台自身分配器；模块不更改 cJSON 全局钩子。cJSON 公共解析接口没有单独的内存不足错误码，因此解析失败同时可能代表语法错误或解析器内存分配失败。

配置校验拒绝未知字段、重复字段、错误类型、缺少必需字段、无效摘要标识和非整数尺寸。数值通过 `valuedouble` 检查范围及整数性后转换为 `uint32_t`。布局使用 64 位中间量，输出前检查屏幕边界；坐标上限采用 LVGL v9 的 29 位普通像素坐标范围。卡片数量与文字长度由实际分配结果决定。

## 同源布局

`board_layout()` 先完整验证布局，然后发出返回按钮、页面标题、卡片矩形、卡片标题和正文命令。每个命令包含对象类型、卡片序号、位置、尺寸、文字及摘要来源。布局按配置顺序从左向右填充，跨列宽度由可用宽度按比例取整；当前行空间不足时换行，下一行从当前行最高卡片之后开始。

设备端 `app_main.c` 将命令转换为 `epd_app_button()`、`epd_app_panel()` 和 `epd_app_label()`。所有位置直接使用命令值，正文在固定文本框中换行并裁切。PC 端 `host/preview.c` 编译同一份布局代码并输出命令；`tools/preview_board.py` 只转换命令为 SVG。SVG 中浏览器负责文字排版，因此几何边界同源，字体栅格及文字换行允许不同。

## 页面生命周期

`ONSTART` 关闭页面动画，读取配置和活动屏幕尺寸，验证完整布局，分配正文控件索引，建立页面控件。只有包含摘要卡片时才创建 500 毫秒周期的 LVGL 定时器，创建后立即暂停。

`ONRESUME` 将页面标记为前台，立即读取一次摘要，随后恢复定时器。每次前台轮询先读取 `epd_app_summary_revision()`；序号未变化时直接返回。摘要读取使用 96 字节栈缓冲区，`epd_app_summary_read()` 返回 false 或内容为空时使用配置的空状态文字。所有更新调用 `epd_app_text()`，由平台比较原始文字后决定是否修改标签。轮询开始时捕获的序号在读完后保存，读取期间出现新发布时会在下一周期再次读取。

`ONPAUSE` 清除前台标志并暂停定时器。`ONSTOP` 删除定时器和应用容器，释放正文控件索引、卡片节点、cJSON 解析树及模型。控件容器的删除事件由平台清理输入组和标签保存的原文；app_fwk 继续拥有页面内存和屏幕对象。

## 验证范围

Host 测试编译生产模型及 SDK 实际 cJSON 源码，检查默认模板坐标、参考模板、空看板、SVG 几何映射、摘要样例、用户配置优先级、坏配置、越界与整数溢出。测试还逐次注入模型分配失败与 cJSON 分配失败，检查失败时没有发出绘制命令且跟踪的分配全部释放。cJSON 分配替换仅存在于 host 测试的 `rtthread.h` 适配头，不影响设备端。

设备模型、配置缓冲区、正文控件索引和定时器的分配失败均有显式处理。现有平台 widget 工厂内部依赖 LVGL 的内存分配行为，当前 SDK 配置启用了 `LV_USE_ASSERT_MALLOC`；host 模型分配测试不代表 LVGL 全堆耗尽时能恢复。两种板型的编译和打包已通过，见[验收记录](../../docs/PLATFORM_VALIDATION.md)；app_fwk 实际生命周期、屏幕尺寸初始化和显示效果仍需上板验证。
