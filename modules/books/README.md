# 阅读应用

书架和阅读合并为一个可安装应用，ID 为 `books`，桌面名称为“书架”。格式解析、分页及阅读界面位于应用内，主固件提供存储、字体、输入、模块管理和显示服务。

## 电子书格式

| 格式 | 处理方式 |
|---|---|
| TXT | 原有 UTF-8/GBK 解码、按字节定位及字体度量分页 |
| Markdown | 转换为段落、标题、强调、链接和插图后重新分页 |
| EPUB | 按 OPF spine 顺序读取章节，解析 EPUB 2 NCX / EPUB 3 nav 目录 |
| 分卷 EPUB | 识别 `basepackage.zip` 与 `chapter*.zip`，章节资源缺失时从基础包读取 |
| MOBI | 使用与 Solution 同源的 libmobi 解码，再交给统一排版层 |

重排格式采用统一的文档记录和阅读布局，不执行 HTML 脚本或外部网络资源。
PNG、JPEG 插图与图库共用逐行/分块解码组件，等比缩放后按 16 灰阶显示。
加密或受 DRM 保护的书籍不在当前解码范围内。
书架只识别 `.txt`、`.md`、`.markdown`、`.epub`、`.mobi` 和分卷 EPUB 目录。

## 组成

| 文件 | 职责 |
|---|---|
| `app_main.c` | app_fwk 根页/阅读页生命周期、导航和受管 UI 分步任务 |
| `pages.c` | 书架、阅读正文和阅读菜单；保持原布局 |
| `bookshelf.c`、`reader.c` | 内部存储与 TF 卡根目录扫描、UTF-8/GBK 解码和文件位置 |
| `ui_bookshelf_data.c`、`ui_reader.c` | 阅读记录、字体度量分页、索引和断点续读 |
| `document/` | 文档工作线程、统一记录和插图缓存 |
| `formats/` | ZIP/XML/HTML、EPUB、Markdown 转换 |
| `codecs/` | MOBI 私有动态解码库 |
| `image/`、`../common/image/` | 书籍流适配和与图库共享的图片解码 |
| `command.c` | `svc books bookshelf|reader` 串口命令 |

应用使用全局输入设备，页面只提供翻页、菜单等业务语义，不注册硬件按键。
平台负责字体、状态栏、存储、系统设置和输入组；阅读内文本设置直接进入平台页面，返回时比较设置，必要时按原文字节偏移重新分页。
导航栈、screen 和页面上下文由 app_fwk 管理。

## 构建和安装

在仓库根目录执行：

```powershell
. .\SiFli-SDK\export.ps1
scons -C project --board=dpi-hdk_lb57gyd7n6_epd_hcpu -j8
scons -C modules APPS=books -j8
```

首次先编译平台；已有配套固件时，只需执行应用构建命令。
应用构建编译 `modules/books/output/books.so` 及私有解码库，校验全部外部符号，并生成
`project/build_dpi-hdk_lb57gyd7n6_epd_hcpu/app-resources/books/`：

```text
books/
  app.json
  books.so
  files.sha256
  icon.ezip
  codecs/
    bk_mobi.so
  res/
    licenses/
```

构建按声明的资源生成新包，并整体替换上述生成目录；已移除的库和资源不会残留在新包中。

将整个 `books` 目录复制到 TF 卡的 `apps/`，在设置 → 应用管理 → 应用安装中安装。
MOBI 解码库属于书架安装包，不作为桌面应用单独安装。打开 MOBI 时才加载私有库，关闭文档并完成后台清理后释放；私有库的内存计入书架应用。
入口图标是包内独立文件，不需要执行应用入口。首次安装可选择内部存储或 TF 卡，程序、图标和私有解码库
分别位于 `/flash/apps/books/` 或 `/sdcard/.epd/apps/books/`。更新沿用原位置；更换位置先卸载再重装，阅读记录保留。
主固件与应用包必须具有相同的构建配置标识；平台接口变化后要一起重新编译，包括天气等已安装模块。

出厂镜像不自动包含应用；需要预装书架时显式传入 `STORAGE_IMAGE=1 PREINSTALL=books`。
烧录该镜像会覆盖内部文件系统；已有设备可通过 TF 卡安装/更新应用包，保留内部用户文件。
批量构建和预装列表见 [平台与应用构建](../../docs/BUILDING.md)。
安装器会在目标存储上暂存完整新包，再替换旧包。更新前需要为新包及文件系统开销留出空间，不能仅按新旧包的大小差计算；MOBI 私有库也计入书架包的存储占用。

## 服务与数据

清单声明 `background: true`。平台在开机、安装完成及存储恢复后装载服务，读取最近阅读记录。
格式解析和插图解码在书架的文档工作线程中执行；文字度量、分页和控件更新仍通过 `ui_process` 在 UI 线程分步执行。后台线程不访问 LVGL 控件或 LVGL 字体对象。
前台总页数完成时只更新一次底栏，不为统计页数重绘正文。
卸载/更新或存储释放时，等待页面、显示和在途命令结束，关闭文件并释放字体、缓存和互斥锁，再释放模块引用。

## 重排文档

EPUB、Markdown 和 MOBI 先转换为与字号无关的文档记录，再按当前字体、字号和边距分页。阅读位置保存转换版本、记录位置与记录内 UTF-8 偏移；调整字号后重新确定该位置所在页，不直接复用旧页码。

文档记录和 4 位灰度插图写入应用安装卷的 `cache/books/documents/`：内部应用使用 `/flash/cache/books/documents/`，卡内应用使用 `/sdcard/.epd/cache/books/documents/`。缓存按实际写入、同步和关闭文件的结果处理，不设置单本文档容量配额或预扣可用空间；保留目标文件接口的有符号 32 位寻址边界。存储空间不足、存储读写失败和 RAM 申请失败分别报告。记录先执行文件同步再发布可读边界，读端随发布版本重新打开文件，兼容 LittleFS 的文件可见性。退出文档后清理临时记录；当前不复用非 TXT 文档的跨会话解析缓存和分页索引。

重排文档按需准备前后各一页的布局与字形。预备任务不更新阅读进度或触发屏幕刷新，邻页缓冲实际申请失败时跳过预备，不以共享池剩余 1 MiB 为门槛。分页与目录索引按需增长，保留数组长度和导航整数的表示范围检查。工作内存、私有库与缓存按会话动态申请，MOBI 私有解码库仅在需要时加载。

文档处理失败时保留当前画面，并提示返回书架重新打开；不把不完整的缓存当作全书。失败会话调整文本设置时重新启动文档转换，使用内存中最后显示位置恢复阅读。正常会话调整字号只重排已有文档记录，不重复转换源文件。重排期间点击阅读菜单的确认，等待原文位置恢复后执行，不用旧页码打断位置恢复。

支持的格式不等于完整复刻各格式的所有排版特性。重排格式支持基础样式、目录、链接及 PNG/JPEG 插图，不支持完整浏览器 CSS、SVG/GIF 插图、嵌入字体、脚本或 DRM。具体边界见 `formats/README.md` 与各 `codecs/*/README.md`。复杂文档仍可能达到当前设备的内存或缓存容量上限。

阅读记录和 TXT 分页索引通过平台分别解析 `data/books/`、`cache/books/`，与应用安装在同一卷。
旧 `/flash/data/reader/` 在目标为空时改名为 `/flash/data/books/`，卡内应用再由安装器迁移至卡内；
旧分页缓存重新生成。旧 TF 卡 `.epd_reader/` 记录仍可迁移读取；卸载应用不删除阅读记录。
源码保留文件互斥保护，串口调试命令会占用当前阅读引擎；调试时切换或关闭书籍将使原阅读会话失效，需要返回书架重开。

## TXT 首次分页

- 每轮使用 8 ms 的软时间预算，逐行推进，可完成多页；到达预算后保存未完成页的状态，交还 UI 循环。单行度量和同步文件读取不可抢占，因此 8 ms 不是最长阻塞时间。待显示页已有索引时，优先显示该页。
- 原文使用 8 KiB 预读缓存。索引和显示各有独立的 8 KiB UTF-8 窗口及原文字节映射，保留跨页预读，只在补充空间不足时搬移剩余数据。原文解码仍以 1024 字节为一段，保留 UTF-8、GBK 和 CRLF 边界处理。
- 分页专用字体代理缓存 1024 个字符的实际字宽，占用约 8 KiB；未命中时查询真实字体，包括字重和回退字体的宽度。字宽缓存不生成位图，与下述字形像素缓存分别管理；重排时清空字宽缓存。
- 外部字体先导入内部 `/flash/fonts/`，然后全量载入 SDK 的 PSRAM 缓存池。字号变化时通过引用计数共享同一文件内容，最后一个字体释放后回收；内容签名参与原有分页索引校验。PSRAM 空间不足时回退为内部文件字体，字体缺失时继续使用内置字体。

正文仍使用原字体和 LVGL 换行规则，阅读位置仍保存原文字节偏移。分页计算不触发重绘，完成后仅更新一次阅读底栏的总页数。预读和字宽缓存相较原实现合计增加约 75 KiB，外部 TTF 另外占用与文件大小相同的 PSRAM。

## TXT 翻页缓存与进度保存

翻页先更新内存中的原文位置、书架记录及当前页。阅读记录通过 SDK 的常驻系统工作队列延后 100 ms 写入内部 Flash，连续更新合并为最新快照，写入失败间隔 1 秒重试。后台工作不读取页面控件或书架对象，仍采用校验记录、双槽与临时文件替换。

退出阅读、切换书籍、重新扫描书架和卸载模块前同步未完成的记录；模块卸载前取消并等待写盘回调结束。平台 `app_service_flush()` 为 UI 线程提供受控关机保存入口，板级 `board_prepare_to_sleep()` 在外设下电前调用它，保存失败时不继续下电。该入口不等于已经实现完整关机状态机；突然断电仍可能丢失尚未写入的最新位置。

当前 SF32LB57 板级有 16 MiB PSRAM：

| 用途 | 预算 |
|---|---:|
| 应用、图像、TTF 文件、字形描述/像素和阅读工作内存共享池 | 11 MiB |
| LVGL 对象及缓存节点工作堆 | 2 MiB |
| LVGL 显示缓冲区和 EPD 新旧像素缓冲区 | 约 2.48 MiB |
| 未分配空间 | 约 528 KiB |

阅读字形复用 LVGL 按字节容量淘汰的 LRU 缓存，计费上限为 8 MiB，并按共享池的实际余量增长，不预占整块像素池。每项按位图字节数加 256 字节的保守管理开销计费，取消原先的 1024 字节最低计费；另以 8192 个节点限制 LVGL 工作堆开销。像素增长给其他分配保留 1 MiB，并为尚未生成的字形描述保留预算。描述表按 Unicode 每 256 个字符分块申请 PSRAM，分块内容合计上限 1 MiB，实际只申请用到的块。描述缓存直接接入真实字体回调，因此分页和正文绘制都能复用字宽、偏移、字形编号等完整信息；Tiny TTF 原来的 32 项缓存仅作为小工作缓存。

缓存键区分字体实例和字形编号；更换字体、字号或字重时失效，释放前等待 GPU 完成读取。新 TTF 文件载入和新模块装载前，可淘汰阅读像素缓存以腾出空间。生成和复制后的位图继续执行 PSRAM 缓存写回，未缓存成功时保留 Tiny TTF 的正常绘制路径。

完整 TTF 文件和栅格化后的字形像素不是同一种数据：外部 TTF 尽量全量载入共享池，内置 MiSans 启动时从 Flash 解压至 PSRAM，系统各字体共用一份只读数据。缓存范围是当前书籍实际出现的字符；容量不足时优先保留近期及相邻页字形，不承诺整本书所有字符同时常驻。

阅读会话保留当前页、上一页和下一页的已排版文本，并优先预生成下一页、上一页所需字形，再从书籍开头向结尾扫描。136 KiB 的 Unicode 位集合用于字符去重，整书扫描游标不随翻页重置；字号、字体或编码重排时才重新扫描。远处字符仅填充剩余容量，不主动淘汰近期字形；像素容量不足时仍继续扫描和准备字形描述。预备任务在阅读前台的 UI 空闲步骤中持续推进，每轮使用 8 ms 软预算，可与面板波形发送重叠；单行排版、单字栅格化和一次文件读取不可抢占，因此预算不是最坏响应时间。预备任务不修改阅读位置或界面版本号，不触发屏幕刷新。

阅读文本、原文字节映射、分页索引、邻页文本和去重集合均通过 `epd_app_alloc/epd_app_realloc(..., EPD_APP_PSRAM)` 动态申请共享 PSRAM，关闭会话时释放；小型实时工作数据可选择 `EPD_APP_SRAM`。这些接口复用 SDK 的 RT-Thread 堆，PSRAM 申请失败不会将大缓冲区转移到 SRAM。必须使用配套的 `epd_app_free`，不能与 `lv_malloc` 或带标签的 SDK `app_cache_alloc` 混用。模块装载器继续使用 SDK 原有的动态分配路径，与阅读共享同一 PSRAM 堆。

整书扫描结束只记录一次 `book characters: unique=..., prepared=...`；其中 prepared 是扫描时成功准备或已存在的字符数量，不等于此刻常驻的像素项数。关闭最后一个阅读字体时记录 `dsc hit/miss`、`draw bitmap hit/miss` 和 `prepared`，其中绘制位图命中统计排除了预生成调用，便于上板确认实际复用情况。

## 上板检查

1. 打开 TF 卡和内部存储的 UTF-8/GBK TXT，快速翻页后退出、重进，确认原文位置和书架焦点恢复。
2. 修改字号、行距、边距及编码后返回，确认重新分页；只完成总页数时，正文不重绘。
3. 大文件分页期间返回桌面，等待完成后重进，确认索引和进度正确。
4. 反复进入、返回、卸载和重装，确认没有残留文件句柄或持续内存增长；卸载后桌面入口消失。
5. 阅读和后台分页期间拔卡，确认平台先停止模块并关闭文件，插卡后可以重新打开。
6. 同一书页停留片刻后连续向后、向前翻页，对比冷缓存翻页和邻页预备后的响应；字号切换后确认正文、分页与进度一致。
7. 快速翻页后立即返回、重新打开和正常重启，确认最后阅读位置保存；检查字体缓存填满后的内存稳定性和字形显示。
8. 分别打开 EPUB 2、EPUB 3、分卷 EPUB、MOBI 和 Markdown，检查中文、目录、插图、链接、字号变化与断点续读。
9. 更新书架包后重新扫描，确认不支持的文件不出现在书架，原有四类格式的阅读位置保持有效。
10. 打开转换缓存超过 2 MiB 的 MOBI，翻过原先停止的位置；修改字号后立即确认退出菜单，检查正文位置和后续翻页。
11. 缓存实际写入失败时，检查提示是否区分存储故障与内存申请失败；恢复存储后重新打开，或调整文本设置重试，确认可以继续阅读。
