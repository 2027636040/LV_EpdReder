# 微信读书应用设计

## 目的与实现状态

`weread.so` 通过 HTTPS 读取微信读书网页接口，提供扫码登录、双重验证码、书架、章节目录和正文阅读。手机用于确认登录，设备自行获取和排版正文。应用不依赖 `books.so`，不需要手机持续转发书页。

当前[清单](app.json)版本为 3、数据版本为 1，不声明开机常驻后台。登录、账号缓存、封面队列、共享阅读和本地进度均已有实现。已有设备记录确认双重验证登录及书架显示；v3 页面导航取参修复已完成主机回归和两板应用编译，目录、正文、返回重进的板上确认仍未完成，详见[实施与验证记录](../../docs/WEREAD_IMPLEMENTATION_TODO.md)。

## 业务流程与限制

打开应用后，服务读取本地会话，尝试恢复账号及书架。未登录时请求二维码并等待手机确认；需要双重验证时停留在四位数字输入状态，保留原请求和 Cookie，暂停扫码轮询。提交验证码继续同一登录会话，成功后完成会话初始化。验证码错误可重输，过期或次数超限需要重新扫码；返回或重新扫码使旧输入失效。

登录后先发布书目，再串行准备当前可见的八本书封面。选择书籍后获取目录，选择章节或继续阅读时读取正文并交给公共阅读器。书架和目录按页浏览，不设置固定总条数上限，实际容量受数据长度及分配结果限制。

目录优先联网更新，失败时可读取完整缓存。章节依据目录中的 `updateTime` 判断缓存修订，正文校验值用于判断旧内容位置是否可恢复。已经打开的目录保持快照一致，重新进入后再检查更新；服务器没有更新时间时保留零值，不自行推测修订。

阅读器支持结构化段落、标题、基础样式、PNG/JPEG 插图和章节内链接，图片为 16 灰阶。调整字号后按正文位置重新分页。缺少离线图片时显示占位，缺少样式时使用默认排版；降级结果不作为完整排版缓存长期复用。

阅读位置只保存到设备，不上传云端；没有全书批量下载功能。离线打开要求相应书架、目录和章节已有完整缓存，登录及缺失内容仍依赖网络。网页接口可能随服务端变化；账号权限不足、正文片段校验失败和未完成验证不作为成功正文缓存。

## 生命周期与导航参数

根页启动时调用 `weread_start()`，服务同时提供工作线程和 UI 处理入口。工作线程串行处理登录、内容、资源、封面及保存任务；只有正在等待扫码时才按登录周期唤醒，等待验证码不继续轮询。UI 处理入口推进排版、显示及停止后的回收。

页面生命周期由 app_fwk 管理。`ONSTART` 创建页面并读取导航数据；`ONRESUME` 恢复当前操作和结果消费；`ONPAUSE` 停止页面专用更新并取消不再需要的请求；`ONSTOP` 释放快照、图像及页面自有资源。阅读页退出还需解除正文视图、保存位置并完成阅读上下文回收。

页面回调的第二个参数是应用 ID。目录页和阅读页使用 `gui_app_this_page_userdata()` 获取导航参数，通过 `gui_app_this_page_memory()` 取得自己的状态。目录页将章节选择参数保存在自己的页面内存中；阅读页初始化后持有目录结果的引用，销毁时释放。框架延迟创建页面时，参数和目录快照仍需有效，这正是 v3 导航修复处理的边界。

最后一个页面退出、更新、卸载或存储退出时，`weread_stop()` 增加取消代次并请求受管服务停止。后台停止接收旧任务，完成位置写入尝试，关闭阅读工作、封面及客户端；UI 等待页面和显示引用结束后回收剩余对象，平台最后释放模块引用。TF 卡移除会统一停止动态应用，内部安装的微信读书也参与退出，清理后可以重新打开。

## 状态与数据所有权

[weread_service.h](weread_service.h) 定义恢复、登录、验证码、书架、目录、章节和注销操作。提交函数复制输入字符串并返回请求代次；后台发布带代次和修订号的 `weread_result_t`，旧请求结果不能覆盖新页面或另一个账号的数据。

服务和页面通过 `weread_result_retain()` / `weread_result_free()` 共享只读结果。书目、目录、账号及字符串与结果一起存活，页面不保留已经释放结果中的裸指针。封面像素由服务准备后交给 UI，撤销图像前先结束绘图及缓存引用。

公共阅读器的参数指定 `app_id=weread`、派生缓存路径、账号/书籍/章节内容身份及资源回调。UI 保存回调只复制并排队位置；真正写文件发生在工作线程。阅读上下文直到转换工作不再使用之后才释放，关闭页面不等于后台已经结束。

公共 HTTP 在套接字、TLS 和读取阶段检查取消与网络代次；同步 DNS 返回之前无法立即中断。网络变化使旧请求失效，不能把另一网络上的新结果接到原请求中。后台不直接操作 LVGL 控件。

## 持久化与账号隔离

数据位于安装卷的 `data/weread` 和 `cache/weread`：内部前缀为 `/flash`，TF 卡前缀为 `/sdcard/.epd`。账号和 bookId 编码为路径键，章节再用 chapterUid 标识，不使用书架行号作为存储身份。

| 对象 | 保存与恢复规则 |
| --- | --- |
| 登录会话 | `data/weread/session` 保存客户端会话；含登录凭据，验证码不写入文件或普通日志。注销写入有效的空会话记录，阻止恢复旧备份会话。 |
| 书架、目录和章节 | 按账号、书籍和章节隔离；记录具有版本、长度及 CRC，章节另保存内容修订、类型及正文校验值。 |
| 阅读位置 | 按账号和书籍保存 chapterUid、内容校验值及公共阅读器位置；内容身份或转换版本不匹配时不直接使用旧偏移。 |
| 封面、插图及派生排版 | 属于可重建缓存；资源缺失与不完整排版不冒充完整离线内容。 |

章节及图片请求仅使用 HTTPS，第三方图片域名不接收账号 Cookie。用户退出账号清除登录会话，各账号进度及缓存仍按各自身份隔离。位置请求入队并不证明已经落盘；当前服务在后台尝试保存，不能由 UI 提交成功推断突然断电前数据已写入。

## 构建与部署

先依照[构建说明](../../docs/BUILDING.md)构建配套平台，然后在仓库根目录执行：

```powershell
. .\SiFli-SDK\export.ps1
scons -C modules APPS=weread -j8
# 使用已构建的 LCD 载板固件配置
scons -C modules APPS=weread FIRMWARE=build_sf32lb57-lcd-gyd7n6_epd_hcpu -j8
```

安装包输出到所选 `project/build_<board>/app-resources/weread/`。完整复制到 TF 卡 `apps/weread`，通过系统应用安装入口安装或更新，程序、数据和缓存随所选安装卷保存。v3 保持数据版本 1，可保留已有账号数据更新。出厂预装需要显式选择 `PREINSTALL=weread`；烧录文件系统镜像会覆盖原有内部文件系统，不用于保留账号数据的日常更新。
